# 本地多校试点启动

本试点使用 `codex/multischool-foundation` 工作区。运行需要 Docker 和 Node.js，不要求用户自行提供 `DATABASE_URL`。

## 首次启动

在试点工作区根目录运行以下命令。`--assets-from` 应指向本生产仓库的原 checkout，供复制 Git 忽略的 Paper 4 原题资源。此参数不读取相邻原型。

```sh
npm run start:pilot -- --assets-from /absolute/path/to/myoj
```

没有需要复制的原题资源时可以直接运行 `npm run start:pilot`。

启动器先创建独立随机凭据，构建当前工作区的 API、domain 和 web。执行器优先复用本机已有的生产判题镜像，运行在试点独立执行网络中。原镜像不存在时才构建本工作区执行器镜像。

首次启动从正在运行的 `campus-judge-local-db-1` 中只读备份 `campus_demo`，恢复到独立试点数据库。应用新增迁移和运行角色授权时，验证迁移前所有原有业务表的行数与字段指纹一致；055 首次执行仅允许明确的学校归属字段、原校名称及一条归属迁移审计变化，其余字段均参与比对。随后才启动 API、worker、web 和 gateway。不运行正常 demo 初始化，不重设原有账号密码。

入口是 [学校工作区试点](http://localhost:3004/schools)。未登录时直接显示登录表单，登录后进入工作区。使用 `localhost` 可与原系统的 `127.0.0.1:3000` 分开保存会话 Cookie。端口本身无法隔离 Cookie。

试点网络使用四个独立的 `/28` 子网，默认从 `172.30.52.0/28` 至 `172.30.52.48/28`，避免本机 Docker 默认地址池耗尽。若其他网络占用这些地址，可在私有配置中调整 `PILOT_EDGE_SUBNET`、`PILOT_BUSINESS_SUBNET`、`PILOT_EXECUTION_SUBNET`、`PILOT_MAINTENANCE_SUBNET`。不删除其他项目网络。

## 人工核验账号

启动后运行一次下列命令，追加两个试点学校、四个校内核验账号和一个独立平台管理员。重复运行保留原密码和已产生的成员关系；首次平台授予后，重跑不会自动恢复已被撤销的平台授权。

```sh
node --env-file=.campus-local/multischool-pilot/cli.env scripts/seed-multischool-pilot.mjs
```

| 账号 | 用途 |
| --- | --- |
| `pilot.alpha` | Alpha School 管理员 |
| `pilot.beta` | Beta School 管理员 |
| `pilot.teacher` | 领取教师邀请 |
| `pilot.student` | 领取学生邀请、核验跨校成员身份 |
| `pilot.platform` | 平台管理员；创建学校、改名、任命学校管理员 |

随机密码只保存在私有 `.campus-local/multischool-pilot/accounts.json`。这些账号不具备原有学校的全站管理员或教师角色。管理员可创建一次性师生邀请，退出后用另一个核验账号领取，再回到管理员账号刷新成员列表。移除一所学校的成员关系不会删除账号或另一学校的成员关系。原本地账号与密码也保留在副本中，可从账户菜单进入学校工作区。

平台入口为 [平台管理](http://localhost:3004/platform)。`pilot.platform` 使用独立平台授权，不自动成为任何学校成员，也不新建 Luq 账户。普通学校管理员看不到平台入口且接口会拒绝访问。原系统管理员仍管理天行创世纪学校，不自动取得平台权限。

## 给班级分配教师

使用试点学校管理员账号进入「学校工作区 → 班级」，在对应班级行点击「分配教师 / Assign teacher」。名单页也有同名按钮。选择教师档案后确认；同一班级可分配多名教师，一个教师可负责多个班级。

如果选择列表为空，请先到「身份档案」新建教师档案；教师需通过邀请加入本校，并通过「身份档案 → 关联账号」关联其教师成员账号，才能登录查看所带班级。弹窗显示账号关联状态，未关联时也可先分配。移除教师分配可在「查看名单」中移出对应教师，学校档案和账号保留。普通教师账号不显示分配按钮。

## 批量导入学生或教师

学校管理员在「身份档案 → 导入身份」打开导入窗口；班级的「查看名单 → 导入名单」会预选当前班级。下载 CSV 模板，填写 `number`（学号／工号）和 `name`（姓名），或上传相同两列的 XLSX 第一工作表。每次最多 500 行、2 MB。编号以文本保存，模板中的虚构人员请替换后导入。

选择学生／教师及可选班级后，点击「预览导入」。核对学校、类型、班级、计数和逐行状态；没有冲突或无效行时，点击「确认导入」。同编号同姓名会复用已有档案，文件内重复资料只处理一次。发生冲突时整批不写入，需要修正文件后重新预览。预览超过 15 分钟或相关校内资料变化时也需重新预览。提交结果因网络故障无法确认时，保留窗口并使用「重试本次导入」，不会重复建档或重复加入名单。

导入只建立本校档案及所选班级名单。登录仍使用邀请加入学校，再通过「关联账号」显式关联；不会因同名或同编号自动连接其他账号。教师档案已关联时，加入班级名单即可获得该班名单访问权限。

## 重新启动和停止

```sh
npm run start:pilot
npm run stop:pilot
```

后续启动保留试点数据库和所有试用记录，不再从原库覆盖恢复。停止也保留数据卷。初始化记录丢失、已有卷与配置不匹配，或者第一次恢复中断时，脚本会停止并要求明确恢复，避免自动覆盖数据。数据库恢复使用单事务。

维护者在试点工作区可以让 Node 自动读取生成的迁移账号连接，无需手动拼接数据库密码。

```sh
node --env-file=.campus-local/multischool-pilot/cli.env \
  packages/domain/src/provision-school.mjs school-alpha "Alpha School" existing-username
```

CLI 环境只用于维护命令。运行中的 API 使用 `campus_app`，worker 使用 `campus_worker`，不共享迁移账号。执行器没有数据库连接，worker 无权读取学校与成员表。

## 核验范围

多校试点支持邀请加入、成员管理、学校档案、班级名单、056 的平台学校治理，以及 057 的校内课程编写、发布与阅读进度。已加入学校的用户默认进入上次选择的有效学校，可点击顶部校名旁的「切换学校」按钮，再选择「加入其他学校」填写邀请码。用试点管理员先新建档案与班级，再添加名单并关联本校成员。用被指派的教师登录可以查看所带班级名单。055 已把原身份、账号和教学业务归入天行创世纪学校；原校继续使用现有教学入口。新学校账号已禁止访问原校业务接口；新学校题库、作业、判题、Luq 及个人自由注册仍待实施。试点是本地数据独立副本，试点修改不回写原本地站点，也不连接或同步线上服务器。
