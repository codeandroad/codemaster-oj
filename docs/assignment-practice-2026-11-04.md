# 作业练习体验与课程题干整理

日期：2026-11-04–05（本地部署跨日）。范围：本地 3000，未推送或同步线上。以下调整沿用现有作业成绩、首次 AC、Luq 和版本权限规则。

## Luq 提示

原来的整块活动规则同时显示额外奖励条件和翻译、题解开放方式，即使奖励为 0 也显示，导致每道作业题重复出现无效信息。

现在额外 Luq 为 0 时不渲染提示；正数奖励默认只占一行，显示金额和可展开的「奖励条件」。具体达标条件、每学生一次、题解辅助资格及限时任务结算时点保留在展开内容中。此处不再显示翻译或题解支付说明，也不请求其开放策略。实际解锁入口的价格、明确确认、余额和服务端访问限制保持有效。

## 提交次数与完成状态

- 「Attempts」改为「本作业提交」，计数由服务端按稳定学生身份、本作业、固定题目版本查询真实正式提交，包含等待判题或截止后提交，不包含自测、订正或其他入口提交。
- 若同一版本已在其他入口正式 AC，并由既有 D61 规则计入本作业，状态继续显示 AC；本作业没有提交时显示「免重做」，不再以裸数字 0 暗示没有完成。
- 汇总分别显示本作业实际提交过的题数和已解决题数。沿用 AC 不虚构提交，也不重复发放作业积分或 Luq。截止时间和有效成绩计算不随提交计数改变。

## 顺序与继续作答

新增迁移 `050_assignment_problem_order.sql`，给作业增加 `course` / `custom` 显示顺序模式。关联课程的作业默认按章节顺序、章内题目顺序展示；课程外题目放在其后。没有关联课程时沿用保存的题目位置。教师可选择自定义顺序，恢复原保存顺序；已有作业的题目位置、固定版本和分值均保留。

作业详情、题目列表和上一题/下一题使用同一服务端顺序。答题区增加紧凑的当前题序号、完成状态和「下一题」入口；正式判题完成后刷新服务端作业状态。下一题保留作业场景与固定版本，仍有未提交代码确认，不在最后一题绕回首题。只改变显示顺序不解除已提交作业的题目、版本和评分配置锁。

教师编辑器在课程目录加载完成前不展示旧的手动顺序，也不开放选题；加载失败显示重试。此保护同样用于预览和切换关联课程，避免选择过程中顺序闪动。

## 115 道课程题的 Notes

对「Python 专项训练 · 全目录学习路线」17 章、115 道题的准确已发布版本进行审核，通过既有英文公开题面发布接口追加无 Notes 的展示内容。仅移除末尾两种已确认的重复 `## Notes` 说明；Task、Interface、代码、题目版本和样例不改。

原始题目版本作为审计来源保留，课程和作业仍引用原版本；学生所有入口使用审核后的展示。中文 Luq 内容及参考答案本轮未改动。私有生成包、隐藏测试和教师批注不纳入公开题面或源码仓库。

内容处理前保存数据库备份；115 个版本逐一校验，英文/中文界面共 230 次学生接口检查通过，受保护的 27 张业务表内容摘要保持一致。复用现有不可变展示发布机制，没有改写题目版本、成绩、学生代码或 Luq 流水。私有操作记录保存在 Git 忽略的本地目录。
