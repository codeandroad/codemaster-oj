# 从 9618 Paper 4 原卷制作可导入试卷包

本说明供教师和制作试卷包的 agent 使用。当前 Paper 4 是 **Python 3 校内练习与模拟考试**：学生在网页中编程，系统自动运行功能测试，教师再按原卷小题批阅结构与证据。原始 PDF、考生文件 ZIP 和评分细则是制作依据，**不能直接上传为试卷包**。上传物必须是本系统的 [结构化 JSON/ZIP 格式](paper4-import-format.md)。

## 三份原件各管什么

用户提供的外层压缩包包含下列材料；制作时先在本地阅读，不要把外层包直接交给“导入试卷包”。

| 原件 | 用途 | 导入包中的去向 |
| --- | --- | --- |
| `9618_s25_qp_41.pdf` | 英文题意、接口、每个小题的要求与分值，是学生题面的依据 | 整理为三道 `questions[].statement` 和逐小题 `stages`；保留英文，允许为网页阅读重排和准确转述 |
| `9618_s25_ms_41.pdf` | 教师核对评分点、边界和参考实现 | 用来核查 `maxMarks`、自动用例和参考程序；不要作为学生附件或把完整答案写进题面 |
| `9618_s25_sf_41.zip` | 考生运行所需文件 | 内部 `TheData.txt` 进入 Q2 的 `initialFiles`；六个空白颜色文件也作为初始文件，文件名进入 `outputFiles` |

考生文件 ZIP 里还有 `evidence.doc`。当前系统不导入 Word 证据模板，也不自动收集截图；原卷截图要求应映射到 `evidence` 阶段，教师在现有运行记录和作答资料基础上复核。不要把 `.doc` 或 PDF 塞进结构化 ZIP 的 `assets/`：解析器只接收明确引用的小型 UTF-8 文本附件。

## 从原卷到模型的映射

1. **先列出小题与分值。** 一张试卷最多三道 `questions`。此卷的 Q1 为 20 分、Q2 为 25 分、Q3 为 30 分，总和必须恰好 75。每个原卷小题对应一个或数个有稳定唯一 `id` 的 `stages`，不要为了凑 AC 擅自增加原卷没有的要求。
2. **写英文题面。** `statement` 面向学生，按原卷的 `1(a)`、`1(b)` 等顺序组织段落、标题和短列表。保留函数名、参数、文件名、输入输出示例与运行要求；网页重排时可转述，但不能把“输出每次入队结果”改为“只输出成功总数”。`starterCode` 是可编辑起点，不是参考答案；不要强制学生采用原卷没有要求的特定 `if __name__ == '__main__'` 写法。
3. **选每阶段的判定方式。** 可用运行结果验证的接口或输出用 `auto`；确需教师查看源码结构、解释的部分用 `manual`；原卷要求的截图、文件或过程记录用 `evidence`。一题获得 **AC** 表示这题全部自动阶段的全部用例通过，不代表自动得到该题满分；教师仍须为每个阶段给分，才能公布总成绩。
4. **把源文件与产物分开。** Q2 的 `initialFiles` 应含原始 `TheData.txt` 的 72 行和 `Blue.txt`、`Green.txt`、`Orange.txt`、`Pink.txt`、`Red.txt`、`Yellow.txt` 六个空文本。`outputFiles` 列出这六个可回收文件。`inputFiles` 只用于单个用例覆盖输入或预置已有输出，以验证追加行为。每个用例在独立沙箱运行，不能依赖前一个用例留下的文件。
5. **按阶段编写 `runnerCases`。** 键是阶段 `id`，不是 `Q1`/`Q2`/`Q3`。`auto` 阶段必须至少有一个用例；`manual` 和 `evidence` 阶段不要放用例。简单整程序题可用 `stdin`、`expectedStdout`、`expectedFiles`；要调用函数、检查队列指针或类接口，可用教师的 `driverCode`。驱动在隔离判题器中运行，不在 API/网页进程执行。函数驱动不得无意运行学生的顶层主程序而污染状态；用 AST 筛选时也要检查赋值右侧的嵌套调用，例如 `Balloon1 = Defend(Balloon1)` 仍是主程序执行，不能因为它是赋值语句就保留。同时要用完整程序运行用例检查主程序。至少覆盖原卷示例、边界和一类合理错误解，并确认测试没有额外限制正确解。
6. **填写原卷分类。** 在 `paper` 中填写可选的 `examYear`（1900–2100 的整数或 `null`）、`examSession`（`"summer"` / `"autumn"` / `null`，对应 May/June / October/November）和 `examVariant`（整数 41 / 42 / 43 / `null`）。分类保存在试卷版本中，修订与导出均保留；旧包省略这些字段仍可导入。教师和学生的列表均可按年份、考季组合筛选，筛选不改变试卷权限或发布状态。
7. **提供完整的 `referenceSolutions`。** 每道大题键映射到一份可独立运行的 Python 程序。参考程序既要通过公开用例，也要通过隐藏用例；它只在教师端和判题路径保存，绝不可复制到 `starterCode` 或题面。对于需要人工评分的部分，参考程序也应体现原卷要求，方便教师审阅。

当前样卷的阶段拆分可作为核对清单；它是校内练习的自动化映射，不声称逐点代替原卷人工评分细则。

| 题目 | 原卷小题与分值 | 当前映射 |
| --- | --- | --- |
| Q1 | (a) 2、(b) 6、(c) 3、(d) 6、(e)(i) 2、(e)(ii) 1 | 初始队列状态人工复核；`Enqueue`、25 行主程序输出、`Dequeue`、两次出队输出自动测试；运行证据人工复核 |
| Q2 | (a) 7、(b) 6、(c) 5、(d) 2、(e)(i) 3、(e)(ii) 2 | `ReadData`、六色拆分、追加/异常处理、六次存储调用、完整运行自动测试；运行与红色文件证据人工复核 |
| Q3 | (a)(i) 4、(a)(ii) 3、(a)(iii) 3、(b) 2、(c)(i) 2、(c)(ii) 1、(c)(iii) 6、(d) 5、(e)(i) 3、(e)(ii) 1 | 节点/树接口、插入、中序输出和完整运行自动测试；主程序中五个对象由教师复核；运行证据人工复核 |

## 可复制的最小格式样例

下面是一份**仅检验格式**的自包含 JSON；它不是合格的真实考题或合理评分设计。当前系统要求总分正好 75，因此样例把唯一阶段设为 75 分。制作原卷时必须改为上表的逐小题分值、真实测试和参考程序。

```json
{
  "format": "codemaster-paper4",
  "version": 1,
  "paper": { "title": "Format check", "description": "Draft only" },
  "questions": [
    {
      "key": "Q1",
      "title": "Print a word",
      "statement": "Write a program that prints ready.",
      "starterCode": "# Write your program here\n",
      "initialFiles": {},
      "outputFiles": [],
      "stages": [
        { "id": "Q1_run", "title": "Program output", "description": "Check stdout.", "maxMarks": 75, "judgeMode": "auto" }
      ]
    }
  ],
  "runnerCases": {
    "Q1_run": [
      { "id": "prints-ready", "public": true, "expectedStdout": "ready\n" }
    ]
  },
  "referenceSolutions": { "Q1": "print('ready')\n" }
}
```

实际制作优先从 [`examples/paper4-english-practice/build.mjs`](../examples/paper4-english-practice/build.mjs) 和配套的 Q2/Q3 构建文件扩展，不要手工改生成后的 JSON 而忘记更新 ZIP。自包含 [JSON 样卷](../examples/paper4-english-practice/paper4-english-practice.json)与引用文本附件的 [ZIP 样卷](../examples/paper4-english-practice/paper4-english-practice.zip)应产生相同的导入预览。ZIP 的根目录必须有 `manifest.json`；较长题面、驱动、参考程序或文本数据可用 `{ "file": "assets/xxx.py" }` 等引用。除了被引用的附件，不要额外塞文件。

## 导入、验证、发布

1. 核对原件中的题目编号、英文要求、接口名、72 行源数据和 75 分拆分；生成 JSON/ZIP，并在本地运行包解析测试。解析预览不会执行代码，也不会创建试卷。
2. 教师在 **Paper 4 实践评测** 中导入包，查看预览的题数、总分、阶段、用例与参考答案覆盖；确认后创建**草稿**，设置班级与练习时间。预览原始 PDF 或考生文件 ZIP 会报格式错误，这是预期行为。
3. 教师逐题检查题面、起始代码、初始文件、公开/隐藏用例及参考程序。点击参考答案的运行验证，让每个自动阶段的所有用例在隔离判题器中通过。再用至少一份故意错误但可运行的程序确认测试确实会拒绝错误答案；检查正确解不会因隐含的额外规则被误拒。
4. 人工审核题目英文、分值与证据安排后才发布。发布版不可原地改写；后续修改使用新修订草稿，重新运行参考验证再发布。既有学生答卷固定在其开始作答时的版本，不应迁移或删除。

多套草稿可在教师端 **Paper 4 实践评测 → 自由练习题库** 勾选后点击 **批量上架**，直接开放全校自由练习，无需班级和时间。表头可全选当前筛选结果中的未上架草稿，每次最多 100 套；切换年份、考季、分区或归档状态会清空选择。系统核对整批权限、完整用例和当前参考答案验证；任一试卷未满足要求时整批不修改。已发布或归档的试卷不可重复批量上架。修订从详情页单独处理，既有学生答卷保留原版本。

上架后点击 **布置活动**，为一个班级建立独立的班级练习或模拟考试。班级练习的开始/结束时间可选，模拟考试必须设置完整有效的时间窗口（北京时间 UTC+8）。活动固定使用所选的已验证上架版本，独立保存答卷、评分和时间；全校自由练习不受影响。未变更的题目继承来源版本的参考验证，不伪造运行记录。自由练习可在交卷后「再次练习」，历史作答保留；活动维持一次作答。同一来源大题在自由练习、重复练习和多个班级活动中首次正式 AC 共奖励一次 10 积分。

教师可在 Paper 4 试卷列表或详情页**导出 JSON**，用同一个“导入试卷包”入口再次导入为新草稿。导出的是服务器已保存的当前版本；在修订草稿页导出的是该草稿。文件包含隐藏用例和教师参考答案，请作为教师资料保管。导入新草稿时不会自动带入原班级和练习时间，需要重新选择并完成参考验证。

不再使用的整张试卷可在列表或详情页**归档**，也可恢复。归档期间学生看不到试卷，已有进行中答卷只能查看，无法保存、运行或交卷；代码、历史答卷和成绩均保留。恢复后，自由练习可继续；班级活动须仍在原时间窗口内。归档来源自由练习不影响已单独布置的班级活动。已发布的大题应通过修订草稿调整，避免删除已作答版本的评分依据。

`public: false` 隐藏用例的输入、预期输出及驱动不得出现在学生可读的题面、起始代码、公开示例或反馈里。教师参考答案同样仅供教师和隔离 worker 使用。试卷包属于教学素材，不包含账户、密码、数据库连接或部署密钥。大小、文件后缀、用例数和 ZIP 路径限制以 [导入格式](paper4-import-format.md) 与解析器为准。

## 按年份维护历年试卷集

`content/paper4-pastpapers/<年份>/` 存放该年份可导入的自包含 JSON，以及复现它们的构建脚本、原件清单和 `coverage.md`。按原件分别核对夏季/秋季与 41/42/43，不能因为两卷看起来相似就共用题面或考生数据；只有核对题目、分值和源文件一致后才能复用内容，并保留不同卷号。按年份的目录和文件名便于维护，列表筛选仍以 `paper.examYear`、`examSession`、`examVariant` 为准。

原件缺失处应在清单与覆盖说明中使用 `source-gap` 标签，并说明缺少的是题面、评分细则还是考生文件。不要猜测缺失的原始内容。确需另做课堂替代材料时，使用 `synthetic` 标签，在学生可见题面/试卷说明中指出哪些数据或要求是教学构造，并在覆盖说明中记录依据；它不能冒充原始考生文件或未取得的原卷。这些标签是来源说明，不是新增的 manifest 字段。

批量验证和导入使用现有的本机 **3002** 隔离预览环境。在仓库根目录运行以下命令，把 `YYYY` 换成该目录的实际年份：

```sh
node scripts/validate-paper4-pastpapers.mjs --year=YYYY
node scripts/import-paper4-pastpapers.mjs --year=YYYY
```

1. 先运行年份构建脚本生成包，核对原始文件、75 分拆分和分类。解析预览只检查格式，不代替运行验证。
2. 运行 `validate-paper4-pastpapers.mjs`，在已有隔离执行器中执行全部参考用例和空白错误答案对照。检查每题参考结果均为 AC，且没有自动阶段接受空白答案。报告保存在 `.campus-local/paper4-pastpapers-validation/<试卷键>.json`，包括 manifest 的 SHA-256 与验证时间。修改包后必须重跑，不能沿用旧哈希的通过记录；另外保留有针对性的错误解与兼容写法核查。
3. 运行 `import-paper4-pastpapers.mjs`。脚本只接受本机 `localhost` / `127.0.0.1` 的 3002 地址，使用已忽略的 `.campus-local/test-accounts.json` 中**已有教师账户**，不会创建/重置账户，也不运行 seed。每个包必须有当前哈希对应的通过报告。导入结果是未指定班级、时间的草稿，并通过正常参考答案运行入口再次验证；结果记录在 `.campus-local/paper4-pastpapers-import.json`。
4. 重跑导入会复用脚本已跟踪且未被教师修改的草稿；已发布、已归档或检测到教师改动的内容不会被覆盖。此流程不发布、不部署，也不改变既有答卷和成绩。最后由教师按前节要求审核后批量上架全校自由练习；如需班级练习或模拟考试，再单独布置活动。

连接地址、密码与会话数据始终留在忽略的本机文件中；清单、覆盖记录和文档只记录来源、内容哈希和验证结论，不写入登录秘密。

## 交给其他 agent 的任务规格

> 请根据我提供的 `9618_s25_qp_41.pdf`、`9618_s25_ms_41.pdf` 和 `9618_s25_sf_41.zip`，制作 CodeMaster OJ Paper 4 v1 结构化 JSON/ZIP **草稿包**。先核对原件来源与缺失情况，填写 `paper.examYear`、`examSession`、`examVariant`；再列 Q1–Q3 所有原卷小题、英文要求、接口/文件名和分值，逐项映射到 `questions[].stages`，总分严格为 75。学生题面保留英文并按小题分段；不得添加原卷未要求的输入限制或特定 Python 主程序写法。保留 `TheData.txt` 原始 72 行，正确配置六个空颜色文件及输出清单。为每个自动阶段设计公开与必要的隐藏用例，给出每道大题可运行的完整教师参考程序；人工源码点和截图证据单独标记，不能以 AC 代替人工分数。使用本仓库解析器预览 JSON/ZIP，运行全部参考用例及至少一份错误解，列出结果。不要导入原始 PDF/Word，不要泄露隐藏用例或参考答案到学生内容，不要发布；交付结构化包、映射表和验证记录，等待教师审核。
