# 9618 Paper 4 预备课程的本地草稿导入

课程素材保存在 `content/9618-paper4-course/course.md` 与 `problems.json`。前者采用 `codemaster-learning-path` v1 的 Markdown/YAML 格式，后者是标准输入输出型 Python OJ 题目数组。每道题标明从 1 开始的 `chapterNumber`，并提供可运行参考程序、至少两组公开样例和五组正式测试；启用的正式测试权重合计 100。每章至少有一道练习。课程正文、公开样例和初始代码不得包含隐藏用例或教师参考答案。

在 **Paper 4 独立本机预览** 的 worktree 根目录运行：

```sh
node scripts/import-9618-paper4-course.mjs --check
node scripts/import-9618-paper4-course.mjs --import
```

唯一允许的目标是独立预览 `http://127.0.0.1:3002`；脚本拒绝 3000、本机其他地址和远端地址，避免误写原本机系统或 rslab。它使用 `.campus-local/test-accounts.json` 中的本机演示教师/学生账号，不会显示或提交密码。状态保存在被 Git 忽略的 `.campus-local/9618-paper4-course-import.json`；失败后在素材**未变化**的前提下重跑 `--import`，复用相同导入请求键与已创建的课程/题目。素材变更会停止自动续传，避免覆盖教师手工修改的内容。不要删除状态文件来绕过冲突；先核对导入回执和现有草稿。

导入顺序为：本地逐例验证参考程序输出 → 创建课程草稿 → 将题目草稿导入系统校内题库 → 创建专属题目分组 → 等待真实隔离判题器把所有参考程序验证为 AC → 关联章节 → 以学生身份检查草稿不可见。脚本不发布课程、题目，不提交管理员审核，也不改动已有课程。新的完整课程可由教师在列表中预览；学生仍看不到。

当前课程 API 即使对**草稿**也仅允许章节关联校内题库题目，教师又不能创建校内题库。因此导入器使用已有系统校内题库，并以同名专属分组管理这些未发布题；题目本身不因处于校内题库而对学生公开。若以后需要独立题库，可由管理员创建校内题库再为教师授予编辑权限，并在导入前明确调整脚本的题库 ID。发布课程之前，所有关联题目仍须先发布并通过管理员的校内公开审核；导入完成不等于上线。
