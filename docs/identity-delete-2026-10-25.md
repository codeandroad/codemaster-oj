# 身份档案删除与恢复（2026-10-25）

## 使用入口

本地 3000 管理员的「身份档案」列表，对从未激活过的学生或教师显示「删除」，详情抽屉也提供同一入口。确认框明确显示姓名、编号和影响，默认聚焦取消。删除后可切换「已删除」列表恢复。

此功能用于清理误建档案，不是清除学生记录或删除登录账号。已有任何账号历史的档案（包括已解除关联的历史账号）和管理员身份均禁止删除，详情显示原因。已有账号可继续编辑身份资料或在账号管理中停用。

## 数据与服务端规则

- 沿用 `identities.archived_at` 实现可恢复删除，不物理删除身份、班级关系、活动历史名单、Luq 账户或追加式流水。正常名单、班级有效成员和可选学生名单排除已删除身份；已有活动的历史名单保留。
- 原编号仍保留唯一归属。再次新建同类型、同编号档案时提示先恢复并编辑，不通过重新建档重复领取初始 Luq。
- 删除时撤销原激活码；已删除档案不能编辑、签发激活码或注册。恢复后须重新生成激活码，原码不会恢复有效。恢复沿用稳定身份，既有初始 Luq 领取记录防止重复发放。
- `DELETE /api/v1/people/:id` 接收确认时的 `name`、`number`；后台资料已变更时返回 `409 IDENTITY_CHANGED`，要求重新核对。`POST /api/v1/people/:id/restore` 恢复；管理员可用 `GET /api/v1/people?deleted=true` 查看已删除档案。普通列表默认行为保持不变。
- 所有入口沿用 Nest Guard 的会话、Origin、CSRF 校验以及 domain 管理员鉴权。身份行锁与注册/关联使用同一身份锁，避免删除与激活并发产生已删除的登录身份。重复删除/恢复在状态未改变时不重复追加审计。
- 删除标记、激活码撤销和 `identity.delete` 审计同事务提交；恢复与 `identity.restore` 审计同事务提交。审计写入失败时回滚整个操作。前端重复提交锁与处理中禁用不代替服务端校验。

无需新增迁移、数据库授权或判题 worker 权限。未改变成绩、判题、累计积分和 Luq 计价/计奖规则。
