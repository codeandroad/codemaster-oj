# ACSL Intermediate 专题 9 — 有限状态机与正则表达式

## 章节：01. 读一个符号，沿一条边转移

### 学习目标

- 识别初态箭头、转移方向以及双圆圈表示的接受态。
- 记录每次消耗符号后的状态，也记录尚未读入符号的初始状态。
- 在完整输入结束后判断是否接受；遇到不存在的转移立即拒绝。

### 正文

#### 状态记住已读前缀中仍然有用的信息

有限状态自动机（FSA）由有限个状态及带标记的转移组成。本教程使用确定性状态机：对一个当前状态和一个输入符号，至多有一个下一状态。从无来源的初态箭头所指的状态出发。标为 `0` 的边恰好消耗一个 `0`；自环虽然不改变状态名，也要消耗一个符号。双圆圈标记接受态。初态箭头本身不消耗输入。

**只有全部符号已经读完，且当前状态是接受态，才接受该字符串。** 中途经过接受态并不够。如果当前符号没有可走的边，就拒绝，不能跳过这个符号，也不能自行补画箭头。教程图中省略了不存在的转移，没有额外画出拒绝汇点。空串记为 $\lambda$，长度为零，因此不会使状态机离开初态。

本专题的这些约定与正则运算符依据 ACSL 官方有限状态机与正则表达式专题说明。这里的状态机、例题与自测均为原创。

#### 逐符号追踪 `1001`

| 已消耗的前缀 | 刚读的符号 | 当前状态 |
| --- | --- | --- |
| $\lambda$ | — | `S` |
| `1` | `1` | `S` |
| `10` | `0` | `A` |
| `100` | `0` | `A` |
| `1001` | `1` | `B` |

状态序列为 `S → S → A → A → B`。四个符号都读完，最后位于 `B`，所以接受。相反，`010` 的状态序列是 `S → A → B → A`：读完前两个符号时到过接受态，但第三个符号又离开了它。因此拒绝 `010`。

空串 $\lambda$ 的状态序列只有 `S`。`S` 不是接受态，所以拒绝空串。含有 `2` 的输入不在这台机器声明的字母表内，也不会被接受。

### 检查点

**1.** 追踪 `10101` 并判断是否接受。请包含读第一个符号前的状态。

**2.** 追踪 `011`。为什么识别出前缀 `01` 后还不能决定最终结果？

**3.** 对同一台机器，判断 $\lambda$、`0`、`01`、`001` 是否接受。最短的可接受字符串是什么？

**4.** 另一台机器以 `U` 为初态，只有 `U --0→ V`、`V --1→ W` 两条边，且仅 `W` 接受。判断 `01`、`010`、`0`；遇到缺边时指出具体在哪一个符号上失败。

完成标准：每条转移恰好消耗一个符号，写出完整状态序列，在最后一个符号之后检查状态。

### 参考答案

**1.** `S → S → A → B → A → B`。五个符号都消耗完，最后位于 `B`，所以接受 `10101`。

**2.** `S → A → B → S`。前缀 `01` 读完时在 `B`，但最后一个 `1` 又使机器回到 `S`。完整输入结束在非接受态，因此拒绝 `011`。

**3.** 各状态序列为：$\lambda$：`S`，拒绝；`0`：`S → A`，拒绝；`01`：`S → A → B`，接受；`001`：`S → A → A → B`，接受。最短的可接受字符串是 `01`，长度为 2。空串和两个长度为 1 的字符串都不以 `01` 结尾。

**4.** `01`：`U → V → W`，接受。`010`：读完 `01` 到达 `W`，但第 3 个符号 `0` 在该状态没有可走的边，因此在第 3 个符号上拒绝。`0`：`U → V`，完整输入结束在非接受态 `V`，因此拒绝。读完后不接受，与尚未读完就遇到缺边，是两种不同的拒绝原因。

初态为 `P`；只有 `F` 接受。表中的横线表示没有转移，绝不表示“原地不动”。

| 当前状态 | 读 `m` | 读 `n` | 读 `p` | 读 `q` |
| --- | --- | --- | --- | --- |
| `P` | `Q` | — | — | — |
| `Q` | — | `R` | — | `F` |
| `R` | — | — | `Q` | — |
| `F` | — | — | — | — |

任何接受路径都先消耗 `m` 到达 `Q`。在 `Q` 可以直接读 `q` 离开，也可以沿 `Q --n→ R --p→ Q` 返回。这个两条边组成的循环消耗的是**完整的 `np` 块**。重复任意非负次，然后读一个 `q`，结束在 `F`。

对应的语言描述是 `m(np)*q`；其中 `*` 表示紧邻它之前的符号或括号组重复零次或多次。写成数学形式为 $m(np)^kq$，$k\ge0$，长度是 $2+2k$。这里的指数表示重复份数，属于数学记号，不是正则表达式的 `^` 运算符。零个循环得到 `mq`，一个得到 `mnpq`，两个得到 `mnpnpq`。

| 输入 | 完整状态序列或首次缺边 | 结果 |
| --- | --- | --- |
| `mq` | `P → Q → F` | 接受 |
| `mnpq` | `P → Q → R → Q → F` | 接受 |
| `mnpnpq` | `P → Q → R → Q → R → Q → F` | 接受 |
| `mnq` | `P → Q → R`；`R` 没有 `q` 边 | 拒绝 |
| `mnppq` | `P → Q → R → Q`；`Q` 没有 `p` 边 | 拒绝 |

`F` 没有出边，所以在一个可接受字符串后再添加任何后缀都会被拒绝。可以不重复循环，但必须读完整个输入。

#### 顺序和括号都不能省略

`m(np)*q` 与 `mn*pq` 不同。后者只重复 `n`，并强制要求一个 `p`，因此接受 `mpq`。但机器在读完开头的 `m` 后不能立即读 `p`。反过来，机器接受 `mq`，但它缺少 `mn*pq` 强制要求的 `p`。

同样，`(np)*` 不等于 `n*p*`：`nnpp` 满足 `n*p*`，却不满足 `(np)*`，因为交替循环中的每个 `n` 后必须立即接 `p`，然后才能开始下一个 `n`。重复不允许重排符号。

#### 接受态不同，允许停止的位置也不同

如果把 `R` 也设为接受态，就可以在最后一个循环只读完 `n` 时结束。新的语言描述为 `m(np)*q | m(np)*n`：或者沿原出口结束，或者在 `R` 结束。这里 `|` 表示并集，两侧空格仅用于排版。实际测试字符串时使用不带排版空格的紧凑形式。

如果改为把初态 `P` 也设为接受态，则只会在原语言中添加空串 $\lambda$，因为没有箭头能够回到 `P`。改变接受态，只会改变哪些完整路径允许结束，不会产生新的转移。

### 检查点

**1.** 用原机器追踪 `mnpnpnpq`、`mnpq`、`mnq`。对接受的字符串，数出完整 `np` 循环的次数。

**2.** 各找一个只被 `m(np)*q` 接受、只被 `mn*pq` 接受的字符串。解释它为什么违反另一个描述的必需部分。

**3.** 保持所有箭头不变，把 `R` 和 `F` 都设为接受态。判断 `mn`、`mnpn`、`mnp`、`mq`，并给出覆盖两个结束位置的语言描述。

**4.** 改为只有 `P`、`F` 是接受态。判断 $\lambda$、`m`、`mq`。为什么初态可以接受，不代表任何前缀都可以接受？

### 参考答案

**1.** `mnpnpnpq`：`P → Q → R → Q → R → Q → R → Q → F`，接受，三个完整循环。`mnpq`：`P → Q → R → Q → F`，接受，一个循环。`mnq`：`P → Q → R` 后没有 `q` 边，拒绝。只读到 `n` 还不是完整的 `np` 循环。

**2.** `mq` 只属于 `m(np)*q`：它允许零个循环，而 `mn*pq` 仍然要求一个 `p`。`mpq` 只属于 `mn*pq`：其中 `n*` 可以为空，但原机器的 `Q` 没有 `p` 边。

**3.** `mn`：`P → Q → R`，接受；`mnpn`：`P → Q → R → Q → R`，接受；`mnp`：`P → Q → R → Q`，拒绝；`mq`：`P → Q → F`，接受。一个描述是 `m(np)*q|m(np)*n`。第二分支允许在最后的 `n` 前重复零个完整循环，所以包含 `mn`。

**4.** $\lambda$ 使机器留在接受态 `P`，接受。`m` 结束在非接受态 `Q`，拒绝。`mq` 结束在 `F`，接受。语言是 $\lambda\;|\;m(np)^*q$。初态是否接受决定空输入的结果；一旦读入符号，仍要按箭头转移。

## 章节：03. 逐一确认正则运算符的作用范围

### 学习目标

- 按重复、连接、并集的顺序处理优先级，并用括号改变范围。
- 把字符类看成一个字符的选择，包括范围与取反。
- 区分 ACSL 形式记号与具体编程语言的正则语法。

### 正文

#### 表达式描述的是完整字符串的集合

形式正则表达式中，相邻表示连接；`|` 或 ACSL 使用的并集记号 `U` 表示选择；`*` 表示重复零次或多次。括号把完整子表达式组合起来。重复的优先级最高，其次是连接，最后是并集：`ab|cd*` 表示 `(ab)|(c(d*))`，而不是 `(ab|cd)*`。形式记号 $\lambda$ 表示空串，并非输入中的希腊字母。不能直接把数学并集符号或 `U` 粘贴进编程语言正则，并假设所有引擎都把它当作并集。

ACSL 还使用实用正则记号：`+` 表示一次或多次，`?` 表示零次或一次；`.` 在本教程的单行例子中匹配一个任意字符。例如 `ka?b+` 接受 `kb`、`kab`、`kabb`，却拒绝 `kaab`、`ka`。括号会改变范围：`(uv)+` 重复整个两个字符的块，`uv+` 则只重复 `v`。

编程语言的正则库各有方言、标志、转义和搜索接口。本课程使用这里明确说明的 ACSL 运算符，并判断**整个候选字符串**是否属于该语言。搜索到一个子串，并不自动代表整串被接受。本阶段不需要掌握锚点、反向引用或编程语言字符串转义。

#### 一对方括号恰好消耗一个字符

`[D-F]` 表示 `D`、`E`、`F` 之一。`[D-F2-4]` 把两个包含端点的范围合成一次选择，并不表示一个字母后接一个数字。若要两个字符依次出现，应写 `[D-F][2-4]`。除非题目另有规定，匹配区分大小写。

紧跟在左方括号 `[` 后的 `^` 对字符类取反：`[^mx]` 表示除小写 `m`、`x` 之外的一个字符，不是“其他某个字母”。它也能匹配数字或标点。`[^mx]*` 可以匹配空串，因为 `*` 允许整个字符类重复零次。

字符类内部，**不处于首字符位置的 `^` 是字面字符**。因此 `[g^j]` 包含 `g`、`^`、`j`；`[^g^j]` 则排除这三个字符。后一个形式中，只有第一个 `^` 执行取反。类似地，`[r|t]` 包含字面竖线 `|` 以及 `r`、`t`；而类外的 `r|t` 是并集，不接受一个竖线。这些原创示例特意采用与关联真题不同的符号。

#### 逐段分配字符，再检查是否有剩余

考虑 `[D-F][2-5]*[^mx]`：先有一个 `D`–`F`，中间有任意多个 `2`–`5`，最后恰好有一个不是 `m`、`x` 的字符。最小长度为 2：中间带星号的部分可以为空，首尾两个类却必不可少。

| 候选串 | 第一个类 | 带星号的中段 | 最后一个类 | 结果 |
| --- | --- | --- | --- | --- |
| `D2` | `D` | $\lambda$ | `2` | 接受 |
| `F44!` | `F` | `44` | `!` | 接受 |
| `E3x` | `E` | `3` | 禁止 `x` | 拒绝 |
| `D` | `D` | $\lambda$ | 缺失 | 拒绝 |
| `F55^` | `F` | `55` | `^` | 接受 |

同一个字符可能同时满足相邻两段。`D2` 中必须把 `2` 留给最后一个类；若把它分给中间一段，必需的末段就缺失了。接受所需的是至少存在一种有效的完整分段，而不是某种固定的贪心手算结果。

### 检查点

**1.** 用 `[M-P][3-6]*[^az]` 检查 `N`、`M3`、`P66?`、`Q4!`、`N5z`。对接受的候选串，写出三部分的分配。

**2.** 对 `r`、`^`、`u`、`v`、`7`，分别比较 `[r^u]` 与 `[^r^u]` 是否接受。取反类中的第二个 `^` 有什么意义？

**3.** 在 `hl`、`hijkl`、`hjkjkl`、`hi`、`jkl` 上比较 `h(i|jk)*l` 与 `hi|jkl`。解释重复的组和并集的作用范围。

**4.** 用 `ve?f+` 检查 `vf`、`veff`、`veef`、`v`。再分别给出一个被 `(uv)+` 接受而被 `uv+` 拒绝的串，以及一个被 `uv+` 接受而被 `(uv)+` 拒绝的串。

### 参考答案

**1.** `N` 拒绝：缺少最后一个类所需的字符。`M3` 接受，分成 `M`、$\lambda$、`3`；`P66?` 接受，分成 `P`、`66`、`?`。`Q4!` 拒绝，因为 `Q` 不在 `M`–`P` 中。`N5z` 拒绝，因为末尾必须分配给最后一个类的字符是 `z`，而该类排除 `z`。

**2.** `[r^u]` 接受 `r`、`^`、`u`，拒绝 `v`、`7`。`[^r^u]` 拒绝 `r`、`^`、`u`，接受 `v`、`7`。第一个 `^` 取反，后面的 `^` 是一个被禁止的字面字符。这两个类都不会一次消耗两个字符。

**3.** `h(i|jk)*l` 接受 `hl`（零个重复块）、`hijkl`（依次为块 `i`、`jk`）、`hjkjkl`（依次为块 `jk`、`jk`）；拒绝 `hi`、`jkl`，因为它们没有同时满足必需的外层 `h` 和 `l`。`hi|jkl` 只接受 `hi` 或 `jkl`，因此拒绝前三个候选串。它的并集隔开的是两个完整分支，并不表示重复。

**4.** `vf` 接受：零个 `e`、一个 `f`。`veff` 接受：一个 `e`、两个 `f`。`veef` 拒绝，因为 `e?` 至多允许一个 `e`。`v` 拒绝，因为 `f+` 至少需要一个 `f`。`uvuv` 只被 `(uv)+` 接受；`uvv` 只被 `uv+` 接受。前者重复一对字符，后者保留一个开头的 `u`，只重复 `v`。

## 章节：04. 用边界与反例核验语言

### 学习目标

- 系统检查空输入、最小长度、额外后缀以及完整消耗。
- 对相邻范围有重叠的字符类，寻找有效的完整分段。
- 比较状态机与正则表达式，同时分清有限个例子和普遍证明。

### 正文

#### 优先检查最容易暴露假设的边界

按这个顺序检查：确定字母表和必需部分；测试 $\lambda$；测试一个最短候选串；添加或删除一个符号制造近似错误；最后检查重复块。每次拒绝都写明原因。

| 表达式 | 接受空串？ | 短的接受例子 | 有启发性的拒绝例子 |
| --- | --- | --- | --- |
| `a*` | 是 | `a` | `b` |
| `aa*` | 否 | `a` | $\lambda$ |
| `(ab)*` | 是 | `ab` | `aba` |
| `a\|bc` | 否 | `a` | `ac` |
| `(a\|b)c` | 否 | `ac` | `a` |

`a|bc` 提供 `a` 或 `bc` 两个选择；`(a|b)c` 则无论选择哪一支，都必须有最后一个 `c`。重复零份 `(ab)` 不产生任何字符，所以 `(ab)*` 接受 $\lambda$。空串不等于一个字符 `a`，也不等于输入一个印刷的 lambda 符号。

#### 为必需的最后一段留下输入

对于 `[3-6]*[5-8]`，先把最后一个字符留给 `[5-8]`，再检查之前的每个字符是否属于 `[3-6]`。

| 输入 | 重复前缀 | 必需的最后一个字符 | 结果 |
| --- | --- | --- | --- |
| `5` | $\lambda$ | `5` | 接受 |
| `56` | `5` | `6` | 接受 |
| `58` | `5` | `8` | 接受 |
| `65` | `6` | `5` | 接受 |
| `79` | `7` 不在 `[3-6]` | `9` 不在 `[5-8]` | 拒绝 |

如果还有其他分段方式可试，一种分段失败并不足以证明拒绝。这里最后一段固定长为 1，因此预留末字符就消除了分界歧义。更一般的情况需要尝试所有合理边界，但始终不能改变字符的先后顺序。

#### “含有匹配子串”是另一个问题

`cabd` 含有子串 `ab`，但它不属于语言 `ab`：两端的 `c` 和 `d` 没有被消耗。编程语言的搜索接口可能报告匹配成功，但它回答的不是整串接受问题。若用软件核对教程，必须明确选择完整匹配语义及对应的正则方言，不能直接依赖默认搜索行为。

第一课状态机的语言可以写成 `(0|1)*01`。前缀可以是任意二进制串，也可以为空，但最后两个符号必须是 `01`。状态不变式证明了两者的关系：读完任意前缀后，恰好在该前缀以 `01` 结尾时位于 `B`。因此，在输入结束时，这台机器与表达式对所有二进制字符串都一致，而不仅仅是已测试的例子一致。

穷举某个长度以内的所有字符串，可以帮助寻找反例，但不能单凭这一点证明对任意长输入都等价。一个反例已经足以否定等价。例如 `a*b*` 拒绝 `ba`，而 `(a|b)*` 接受它。前者把输入分成先 `a` 后 `b` 的两个阶段，后者允许全程混合选择。

### 检查点

**1.** 用 `[4-7]*[6-9]` 检查 `6`、`46`、`679`、`89`。对接受的候选串，给出准确的前缀与末字符分界。

**2.** 在 $\lambda$、`abba`、`bbb`、`aaab` 上比较 `a*b*` 和 `(a|b)*`。两种语言等价吗？给出一个最短反例，并解释为什么它最短。

**3.** 同时使用第一课转移表和 `(0|1)*01`，判断 `001`、`0011`、$\lambda$、`01`。搜索工具在 `0011` 内找到了 `01`，为什么状态机仍然拒绝完整输入？

**4.** 形式表达式 $\lambda\;|\;cd$ 的字母表是 {c, d}。判断空输入、`cd`、`c`、`cdd`，以及仅含字面印刷字符 `λ` 的输入。为什么把 `λ|cd` 输入编程正则工具，可能得到不同结果？

### 参考答案

**1.** `6`：$\lambda$ 加 `6`，接受。`46`：`4` 加 `6`，接受。`679`：`67` 加 `9`，接受。`89` 拒绝：把 `9` 留给末类后，剩下的 `8` 不属于 `[4-7]`。前缀可以为空，却不能含有范围外的字符。

**2.** 两者都接受 $\lambda$、`bbb`、`aaab`。只有 `(a|b)*` 接受 `abba`：`a*b*` 一旦进入 `b` 部分，就不能再返回 `a`。因此两种语言不等价。一个最短反例是长度为 2 的 `ba`：空串和两个长度为 1 的串 `a`、`b` 都被两者接受，所以不可能存在更短反例。

**3.** `001`：`S → A → A → B`，接受；`0011`：`S → A → A → B → S`，拒绝；$\lambda$：`S`，拒绝；`01`：`S → A → B`，接受。表达式给出相同判断：只有 `001`、`01` 以 `01` 结尾。`0011` 的某个子串在那里结束，但完整输入末尾还有一个 `1`，整串匹配不能把它丢掉。

**4.** 空输入通过 $\lambda$ 分支接受，`cd` 通过另一分支接受。拒绝 `c`（不完整）、`cdd`（多出一个 `d`）和字面输入 `λ`（不在字母表中，也不是空串）。在常见编程正则中，键入的希腊字母 `λ` 是普通字符，因此 `λ|cd` 并不编码形式语言中的空串分支。使用编程工具前必须翻译语义，不能仅凭外形相似就认定等价。
