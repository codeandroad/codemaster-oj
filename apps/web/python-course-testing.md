## 测试流程

1. 教师进入学习内容 → 学习路径 → 导入 Markdown，选择最新版 python-learning-path.md，检查 20 章后导入为新草稿。
2. 打开课程编辑页，「路径资料」中选择封面与难度。当前 Python 文档默认入门、Python 封面，也可改为进阶。
3. 在「Python 配套判题练习」点击「生成 20 道练习并校验」。服务创建独立校内题库，每章对应一道 stdio 题；事务和课程锁防止重复点击生成同一课程的第二套题。
4. 判题 worker / judge 必须真实运行，且 Python 3.12 环境就绪。若提示节点不可用或队列已满，请先处理判题服务，不伪造通过状态。
5. 点击「刷新校验状态」查看结果；全部版本 AC 后才能「发布练习并关联」。题目标题可跳转到题库编辑器查看测试与参考解答。修改成新题目版本后，应在普通题库中完成校验、发布，再在章节编辑中选择正确引用，不依赖原生成版本自动推断新版本。
6. 教师核对课程后发布学习路径。学生进入课程，阅读标记计入阅读进度；配套题正式提交 AC 计入练习进度。运行样例、自定义自测和未公开计时练习的隐藏结果不计入。
7. 教师点击「查看学生进度总览」，只看到所负责班级中的学生；管理员可查看全校。两个进度并列展示，不将已读当成掌握或成绩。

已经成功导入的旧版 20 章资料无需重新导入也可生成同一套练习，前提是章节标题和顺序未改变。新练习全部以数据库生成的 UUID 保存；资料文件不携带伪造 ID。python-practice-pack.json 是教师审阅与本机测试用的完整题目包（含解答和测试），不是学生资料下载，也不放入公开资源目录。

## 数据与状态

课程封面为本地原创矢量素材，键仅允许 python / algorithms / general；不接受远程封面 URL。难度为 beginner / intermediate / advanced，对应入门 / 进阶 / 提高。字段可编辑、导入、导出。

配套题使用现有 problem_versions、test_cases 与真实验证队列，不另造评测逻辑。每题 2 个公开样例、5 个正式测试（权重合计 100），20 题共 100 测试。

阅读进度由 learning_progress 按学生身份保存；任务进度按课程内唯一版本计数，仅采纳同一身份、同一题目版本、正式 submit/correction 的 AC 结果。相同练习被多个章节引用，课程总览只算一个任务；每章目录则显示该章任务数量。没有已发布练习时显示「暂无已发布练习」，不显示虚假的完成百分比。

## 验证范围

100 个标准解答输出已在本机 Python 执行，与独立列出的期望输出一致。这不能替代部署环境中的隔离判题；发布仍由真实验证 AC 作为硬条件。HTTP 路由测试使用真实 Nest 控制器和领域导入逻辑，数据库与认证上下文是测试替身。实际 PostgreSQL 迁移、生产 CSRF 会话和隔离判题全链路需要部署后验收。

此次修复无需额外数据库迁移；如果尚未应用上轮课程功能，仍须按前文执行 014 迁移。已执行迁移的环境更新本仓库源码后重建并重启 API 即可：

## 可上传题目包与章节关联

提供两种格式：python-practice-pack.json 为 Python 配套 v1 包，20 题按原始章节排序；python-practice-import.json 与 python-practice-import.zip 为通用题目数组，可在「导入中心 → 题目 / 测试」上传。每题包含 Markdown 题面、初始代码、Python 参考解、2 个样例和 5 个正式测试。

推荐：教师打开已导入的完整 Python 20 章课程编辑页，先保存章节，再在「Python 配套判题练习」点击「导入配套题目包」，选择 python-practice-pack.json。预览数量后「确认导入 20 道练习」。系统原子创建独立校内题库和全部题目版本并进入真实验证队列；刷新校验状态，全部 AC 后点击「发布练习并关联」，最后发布课程。学生此时才能看到章节练习。校验失败、判题服务未就绪时保持未发布，可点击题目编辑链接处理。

已有配套题目的课程拒绝再次上传，避免重复创建。自定义包必须保留格式版本与 20 个原始章节标题顺序；可编辑题面、样例、测试和参考解。服务端仍执行现有题目校验，不采用文件中的发布状态或校验结果。

通用导入保存题目草稿，不自动关联课程。应在题库中校验、发布，并将题库改为校内公开，再在课程章节中选择题目引用。勿同时使用两种方式导入同一套练习。题目包含教师解答和测试，不放入学生公开下载目录。

更新此入口须重建、重启 API 和 Web；无需新增迁移（上一轮 014 仍需已应用）。

## 校验状态长期停留 Waiting 的显示修复

当前本地部署只读检查确认：20 道 Python 配套题的数据库 validation_status 全部为 AC，判题队列任务已完成。旧课程编辑页只在打开页面或点击刷新时获取状态，导入后仍显示初始 Waiting。

课程编辑页现对 Waiting / Judging 每 3 秒自动获取状态，完成后停止轮询；后台隐藏页面暂停请求，返回后继续。请求失败显示重试提示，保留手动刷新。仅更新 practiceBundle，不覆盖编辑中的章节正文。Waiting、Judging、AC 分别显示排队中、校验中、校验通过，不伪造判题结果。

此轮仅修改 Web，无新增迁移。更新本仓库源码后重建并重启 Web：

```sh
docker compose --env-file deploy/.env -f deploy/compose.yaml build web
docker compose --env-file deploy/.env -f deploy/compose.yaml up -d --no-deps web
```

已有导入题目无需重导。当前页面点击「刷新校验状态」或重新打开即可读取已完成的结果；升级后自动刷新。

## 学习章节进入正式代码编辑页

「开始练习」在当前标签页进入统一代码编辑器，并携带 learningPathId、chapterId、versionId。编辑器读取服务端课程章节数据，验证当前题目及版本属于该章，展示课程与章节来源、本章练习抽屉、章节内上一题/下一题/随机题。题目列表不混入全题库，切题保留课程和固定版本。无效课程上下文不生成章节导航；题目访问和提交权限仍由原有后端执行。

正式 submit AC 或课程返回的已完成状态显示「本题已完成」，可继续下一题或返回章节；样例 AC 不计完成。返回原章节重新获取真实阅读/任务进度，并恢复点击开始练习前的阅读位置。代码草稿和离开确认沿用统一编辑器逻辑，不自动交卷或标记已读。阅读位置保存在当前标签页会话，仅恢复一次。

本轮只修改 Web，无数据库迁移。应用安装包后重建、重启 Web。验证包括课程来源、本章抽屉、固定版本切题、返回章节以及导航单元测试；页面判题状态由 fixture 验证展示，正式判题沿用现有服务。

## 编辑器底部按钮与状态栏

布局设置选择「代码区」时，运行/提交按钮位于代码编辑框内部的右下角，随编辑面板缩放与最大化，不再位于整个工作区底部。左下角显示当前光标行列及本机草稿保存状态，移除「代码与已接收记录一致」。草稿保存状态来自 sessionStorage 的实际写入结果，保存失败明确显示未保存；它不代表正式提交。选择「页面工具栏」仍在顶部显示按钮。

Python 欢迎语题的原始样例和测试输入多写了一个换行（Alice\n\n）。已修正内置题目和三个导入文件为单个结束换行，样例显示省略末尾行终止符，保留中间空行。显示处理不修改已导入版本的真实判题输入，避免变更已经发布的题目版本。已有输入仍可使用，不需要重导；若要修正已导入题目数据，可在教师题库中新建版本后重新校验发布。

应用新版安装包，重建重启 Web 即可使用布局修改；若需要后续生成配套题使用修正后的内置输入，同时重建重启 API。无新增迁移。
