# ACSL Intermediate 专题三：程序追踪

## 章节：01. 每次只执行一行：变量状态与数值操作

### 学习目标

- 用当前状态计算赋值号右侧的整个表达式，再替换左侧变量。
- 按题目规定区分普通除法、整数转换、取余和乘方。
- 记录中间状态，区分最终状态与变量曾经存储过的所有不同值。

### 正文

#### 追踪之前，先明确记号

变量是带名字的存储位置，当前存储的值可以改变。本课程中的 `a = a + 1` 表示“读取 a 当前的值，加 1，再把结果存入 a”。这是赋值，不是待求解的方程；比较两个值是否相等使用 `==`。

先修检查：如果 a 为 6，执行 `a = a + 1` 后存储什么？答案是 7。下面每张状态表都建立在这一步之上。

本课程的伪代码中，`^` 表示乘方，`*` 表示乘法，`/` 表示普通除法，`%` 表示余数。先算乘方，再算乘、除、取余，最后算加减。本课使用的乘、除、取余一组以及加、减一组中，同组从左往右计算。遇到不熟悉的连续乘方表达式，用括号确认分组，不自行猜测结合规则。括号可以改变运算顺序。不要直接套用某种编程语言的符号含义，例如 Python 的 `^` 并不是乘方。

这些例题中，除法与取余的输入均非负，除数为正。ACSL 的 `int(x)` 表示不大于 x 的最大整数，即向下取整。输入非负时，这等同于去掉小数部分，所以 `int(7.75)` 为 7。因此 `31 / 4` 为 7.75，`int(31 / 4)` 为 7，而 `31 % 4` 为 3。商和余数可以合起来检查：$31=4\cdot7+3$，且 $0\le3<4$。负数边界上，ACSL 的 `int(-1.5)` 为 -2，而 Python 的 `int(-1.5)` 为 -1，不能把语言函数直接替换成伪代码函数。上述记号依据 [ACSL 伪代码说明](https://www.categories.acsl.org/wiki/index.php?title=What_Does_This_Program_Do%3F)；本课程的例题与自测均为原创。

#### 例题 1A：只更新赋值号左侧的变量

```text
a = 9
b = 4
a = a - b
b = a + 2 * b
a = b % a
output a, b
```

表格从两条初始化语句都执行完之后开始。后续每行记录相应赋值完成后的状态；没有更新的变量保留原值。

| 状态 | a | b |
| --- | ---: | ---: |
| 初始化后 | 9 | 4 |
| 执行 `a = a - b` 后 | 5 | 4 |
| 执行 `b = a + 2 * b` 后 | 5 | 13 |
| 执行 `a = b % a` 后 | 3 | 13 |

**输出：** `3, 13`

第二次计算读取已经更新的 a = 5 和当前 b = 4，得到 $5+2\cdot4=13$。下一次赋值应先计算 $13\bmod5=3$，再替换 a。任何一步重新使用最初的 9，追踪的都已经不是这段程序。

两个变量曾经存储过的不同值组成集合 $\{3,4,5,9,13\}$，共有五个。中间乘法 $2\cdot4=8$ 不会把 8 加入该集合，因为没有变量存储 8。重复出现的 4 只计一次；初始化值需要计入，最终输出则不包含完整的变化历史。

#### 可以反复使用的追踪方法

先把变量名写成表头。每遇到一条实际执行的赋值，读取当前行，算完右侧表达式，再只修改左侧变量所在的列。另列输出记录：打印一个值通常不会改变变量。如果问“曾经存储过多少个不同值”，就在状态表旁维护一个集合。

进入条件分支之前，应能解释为什么交换两条赋值语句可能改变结果：后面的右侧表达式可能需要前面刚刚更新的值。

### 检查点

**1.** 分别追踪原程序与调换赋值顺序后的程序，解释输出为什么不同。

原顺序：

```text
a = 7
b = 2
a = a + b
b = a - b
output a, b
```

调换两条赋值：

```text
a = 7
b = 2
b = a - b
a = a + b
output a, b
```

**2.** 写出输出，并用商与余数的关系验算。

```text
n = 31
q = int(n / 4)
r = n % 4
output q, r
```

**3.** 在第 1 题的原顺序程序中，a 或 b 在执行过程中共存储过多少个不同值？包括初始化，同一个值不能重复计数。

完成标准：先写出状态表，再核对答案；能说明每个右侧表达式读取的是哪个时刻的值。

### 参考答案

**1.** 原顺序中，第二次更新使用的是 a = 9。

| 状态 | a | b |
| --- | ---: | ---: |
| 初始化后 | 7 | 2 |
| 第一次更新后 | 9 | 2 |
| 第二次更新后 | 9 | 7 |

**输出：** `9, 7`

调换顺序后，b 先变成 5，再用于更新 a。

| 状态 | a | b |
| --- | ---: | ---: |
| 初始化后 | 7 | 2 |
| 第一次更新后 | 7 | 5 |
| 第二次更新后 | 12 | 5 |

**输出：** `12, 5`

两次赋值按顺序执行，并不是同时更新。若所有右侧表达式都只使用初始值，就会漏掉这种依赖关系。

**2.** 普通除法得到 7.75，`int` 保留 7，余数为 3。

| n | q | r |
| ---: | ---: | ---: |
| 31 | 7 | 3 |

**输出：** `7, 3`

独立验算为 $31=4\cdot7+3$，且 $0\le3<4$。

**3.** 集合为 $\{2,7,9\}$。初始化的 7 和后来再次出现的 7 是同一个集合元素。

**输出：** `3`

## 章节：02. 条件决定路径：分支、边界与反例

### 学习目标

- 区分一条 `if / else if / else` 分支链与多条独立的 `if`。
- 用执行到相应位置时的状态判断嵌套条件。
- 从要求的输出反推条件，并用精确的边界输入反驳错误规则。

### 正文

#### 条件判断发生在一个具体时刻

在一条 `if / else if / else` 链中，选择第一个为真的分支，并跳过这条链中其余分支。后面另一条独立的 `if` 则是新的判断，它可能读取前一个分支修改过的值。缩进和对应的 `end if` 用来区分哪些语句属于同一层结构。

`and` 要求两项比较都为真；`or` 只需至少一项为真。用括号明确每项比较的范围。被跳过的赋值不会改变状态，也不会给第一节所说的“曾存储值集合”增加元素。

#### 例题 2A：后面的条件读取更新后的状态

```text
score = 7
bonus = 2
if score < 6 then
    bonus = bonus + 4
else if score < 9 then
    score = score + bonus
else
    bonus = 0
end if
if (score % 3 == 0) and (bonus > 0) then
    score = score - 1
end if
output score, bonus
```

| 状态 | score | bonus |
| --- | ---: | ---: |
| 初始化后 | 7 | 2 |
| 第一条分支链结束后 | 9 | 2 |
| 独立 if 结束后 | 8 | 2 |

**输出：** `8, 2`

先判断 `7 < 6` 为假，再判断 `7 < 9` 为真，于是 score 变成 9。值发生变化，并不意味着重新从这条分支链的开头判断。到后面的独立 `if` 时，`9 % 3 == 0` 与 `2 > 0` 都为真，score 因此变成 8。未被选择的 `bonus = 0` 从未执行。

#### 例题 2B：两次独立判断

```text
x = 4
if x < 5 then
    x = x + 2
end if
if x > 5 then
    x = x * 3
end if
output x
```

| 状态 | x |
| --- | ---: |
| 初始化后 | 4 |
| 第一条 if 结束后 | 6 |
| 第二条 if 结束后 | 18 |

**输出：** `18`

第二次判断会执行，读取的是 6，而不是 4。

#### 例题 2C：一条互斥分支链

```text
x = 4
if x < 5 then
    x = x + 2
else if x > 5 then
    x = x * 3
end if
output x
```

| 状态 | x |
| --- | ---: |
| 初始化后 | 4 |
| 已选分支结束后 | 6 |

**输出：** `6`

第一个分支被选中，`else if` 就会被跳过，即使更新后的值已经大于 5 也一样。只改这一处结构，就足以改变程序结果。

#### 从输出要求反推测试输入

要得到某个指定输出，先找出通向它的执行路径及路径上的条件，再从初始化开始检验候选输入。如果程序还会打印不需要的消息，仅仅到达其中一条目标输出语句并不够。

遇到数值边界 k，在合法输入范围内分别测试 k 本身、略小于 k 和略大于 k 的值，便于发现 `<` 与 `<=` 的差异。一个失败输入就足以反驳“对所有合法输入都正确”；几个成功样例不能证明这句话，还需要说明各分支覆盖的区间如何衔接。

对于分段收费，应区分“每一项都使用这个费率”与“只有超出边界的部分使用这个费率”。下面的原创检查点只用两档收费，便于看清每个费率究竟乘以哪个数量。

### 检查点

**1.** 追踪程序，并指出第二次条件判断读取的状态。

```text
x = 6
y = 3
if x % 2 == 0 then
    x = x + y
else
    y = y + 2
end if
if (x > 8) and (y == 3) then
    y = x - y
end if
output x, y
```

**2.** 哪个候选输入恰好先打印 `LARGE`、再打印 `READY`？输入均为整数。A：(0, 3)；B：(4, 1)；C：(5, 0)；D：(6, 2)。包括被排除的选项在内，逐个追踪。

```text
input n, token
if n < 1 then
    output "INVALID"
else
    if n <= 4 then
        output "SMALL"
    else
        output "LARGE"
    end if
    if token > 0 then
        output "READY"
    end if
end if
```

**3.** 打印机的前两页每页收费 3 枚代币，之后每增加一页收费 1 枚。页数 p 为正整数。有人建议在所有 $p>2$ 的情况下使用 $6+p$。请给出反例、改正该表达式，并计算 p = 1、2、3、5 时的费用。

完成标准：写出实际执行的路径，区分“被跳过的分支”与“之后重新判断但为假的条件”，说明边界反例为什么足以排除错误公式。

### 参考答案

**1.** 6 是偶数，第一个分支把 x 改成 9。第二次判断读取 x = 9、y = 3，两项比较均为真。

| 状态 | x | y |
| --- | ---: | ---: |
| 初始化后 | 6 | 3 |
| 第一条 if 结束后 | 9 | 3 |
| 第二条 if 结束后 | 9 | 6 |

**输出：** `9, 6`

**2.** 要打印指定的两条消息，必须进入外层合法输入分支，n 大于 4，且 token 大于 0。

| 候选 | n | token | 打印顺序 |
| --- | ---: | ---: | --- |
| A | 0 | 3 | INVALID |
| B | 4 | 1 | SMALL, READY |
| C | 5 | 0 | LARGE |
| D | 6 | 2 | LARGE, READY |

**输出：** `D`

A 根本不会到达内层 READY 判断；B 恰好落在SMALL 分支的边界上；C 会打印 LARGE，但不满足独立的 READY 条件。

**3.** p = 3 时，正确费用为 $3+3+1=7$，而 $6+p$ 得到 9，把前两页又算了一遍。因此 p > 2 时应使用 $6+(p-2)$；$1\le p\le2$ 时使用 $3p$。

| p | 费用 |
| ---: | ---: |
| 1 | 3 |
| 2 | 6 |
| 3 | 7 |
| 5 | 9 |

**输出：** `3, 6, 7, 9`

这条规则覆盖了全部正整数：第一段包含 2，第二段从 3 开始；前两页之后每增加一页，费用恰好增加一枚代币。

## 章节：03. 重复也有顺序：循环与终止

### 学习目标

- 列出真正进入 `for` 循环体的值，处理正负步长以及是否能够到达终点。
- 区分 `while` 判断时的值与循环体执行后的状态，包括循环执行零次的情况。
- 在需要时保存旧值，并说明循环为什么会结束。

### 正文

#### 先数执行次数，再计算

本节 `for k = start to end step s` 的约定是：正步长时，k 不大于 end 就进入循环体；负步长时，k 不小于 end 就进入循环体。只有按步长恰好走到终点时才包含终点。例如 `2 to 8 step 3` 进入循环体的值为 2、5、8，下一候选值 11 不再进入。本节不使用循环结束后的控制变量，不同语言可能对它留下不同的状态。

`while` 在每次执行循环体之前检查条件。如果第一次判断就为假，循环体执行零次。循环体内部的赋值仍然按顺序执行，循环不会把这些语句变成同时更新。

#### 例题 3A：把累计值带到下一段循环

```text
total = 1
for k = 2 to 8 step 3
    total = total + k
next k
for k = 6 to 2 step -2
    total = total - k / 2
next k
output total
```

| 循环体执行序号 | k | 执行后的 total |
| ---: | ---: | ---: |
| 1 | 2 | 3 |
| 2 | 5 | 8 |
| 3 | 8 | 16 |
| 4 | 6 | 13 |
| 5 | 4 | 11 |
| 6 | 2 | 10 |

**输出：** `10`

程序中没有第二条 `total = 1`，所以第二段循环从 16 继续。把所有变化合起来独立验算：

$$
1+(2+5+8)-(6/2+4/2+2/2)=1+15-6=10.
$$

不能把终点值当成执行次数：第一段循环体执行三次，并不是八次。

#### 例题 3B：先判断，再更新，再次判断

```text
n = 23
ones = 0
turns = 0
while n > 0
    bit = n % 2
    ones = ones + bit
    n = int(n / 2)
    turns = turns + 1
end while
output ones, turns
```

| 执行前 n | bit | 执行后 ones | 执行后 n | turns |
| ---: | ---: | ---: | ---: | ---: |
| 23 | 1 | 1 | 11 | 1 |
| 11 | 1 | 2 | 5 | 2 |
| 5 | 1 | 3 | 2 | 3 |
| 2 | 0 | 3 | 1 | 4 |
| 1 | 1 | 4 | 0 | 5 |

**输出：** `4, 5`

第五次循环体结束后 n 为 0，接着的条件判断为假，不会产生第六次执行。每个正整数 n 都被替换成更小的非负整数，因此最终会到达 0。还可以独立检查：$23_{10}=10111_2$，五个二进制数位中有四个 1。取余时从最低位开始，所以余数产生顺序与数位书写顺序相反，但不影响统计 1 的个数。

如果 n 初始为 0，这段程序会输出 `0, 0`。这是程序的行为，并不表示写出来的数码 0 没有数位。应把程序实际计算的问题与看起来相似的数学描述分开。

#### 需要旧值时，先保存再覆盖

如果两个新值都需要旧的 a，就先执行 `old = a`，再修改 a。后面的 `b = a` 读取的是新 a，而 `b = old` 读取保存下来的旧值。可以用不变量检查：它是每次完整循环体结束后都成立的关系。应根据更新公式验证它，不能只因第一行碰巧满足就默认它一直成立。

### 检查点

**1.** 求输出，再只把循环终点 3 改为 4，求新的输出。两种情况下都列出真正进入循环体的 k 值。

```text
total = 0
for k = 9 to 3 step -3
    total = total + k
next k
output total
```

**2.** 按题面 n = 10 追踪，再分别把初始化改为 n = 1、n = 0，写出对应输出。

```text
n = 10
count = 0
while n > 1
    n = int(n / 2)
    count = count + 1
end while
output n, count
```

**3.** 追踪以下更新过程，解释为什么需要 old，并核对每次循环体结束后 a 与 b 的差。

```text
a = 3
b = 1
turns = 0
while a < 15
    old = a
    a = 2 * a - b
    b = old
    turns = turns + 1
end while
output a, b, turns
```

完成标准：说明用于条件判断的是哪些状态，数循环体执行次数而不是判断次数，不多执行一轮就能解释终点。

### 参考答案

**1.** 进入循环体的值为 9、6、3。

| k | 执行后的 total |
| ---: | ---: |
| 9 | 9 |
| 6 | 15 |
| 3 | 18 |

**输出：** `18`

终点改为 4 后，只有 9、6 进入；下一候选值 3 已经小于 4。

| k | 执行后的 total |
| ---: | ---: |
| 9 | 9 |
| 6 | 15 |

**输出：** `15`

**2.** n = 10 时，循环体把 n 依次变为 5、2、1。

| 执行后 n | count |
| ---: | ---: |
| 5 | 1 |
| 2 | 2 |
| 1 | 3 |

**输出：** `1, 3`

两个边界输入在第一次判断 `n > 1` 时就不成立。

| 初始 n | 最终 n | 最终 count |
| ---: | ---: | ---: |
| 1 | 1 | 0 |
| 0 | 0 | 0 |

**3.** 表中每一行都在整个循环体结束后记录，包括计数器更新。

| a | b | turns |
| ---: | ---: | ---: |
| 5 | 3 | 1 |
| 7 | 5 | 2 |
| 9 | 7 | 3 |
| 11 | 9 | 4 |
| 13 | 11 | 5 |
| 15 | 13 | 6 |

**输出：** `15, 13, 6`

初始时 $a-b=2$，更新后的差为 $(2a-b)-a=a-b$，所以差始终是 2。因此 a 每轮增加 2，六轮后 $3+2\cdot6=15$，下一次条件判断为假。如果把 `b = old` 改成 `b = a`，b 就会等于刚更新的新 a，第一行变成 (5, 5)，不变量被破坏，之后 a 每次更新仍为 5，循环将无法结束。保存旧值是算法的一部分，并不是可有可无的书写习惯。
