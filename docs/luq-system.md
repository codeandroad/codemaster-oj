# Luq 助学点：实现、配置与升级

Luq 是独立的可消费助学点，用于取得获授权的学习辅助内容。成绩、个人累计积分、全校榜分继续使用原来的计算与流水；同一次可信业务事件可以分别触发它们。Luq 不兑换历史积分，不提供现金充值、转账、商城或余额排行榜。

本说明对应迁移 `043_luq.sql`、`044_luq_initial_grant.sql`、`045_luq_assistance_prices.sql`、`046_luq_content_batches.sql` 和 `047_problem_public_statements.sql`。设计决策见 [D47](campus-judge-design-summary.md#decision-d47)、[D48](campus-judge-design-summary.md#decision-d48)、[D49](campus-judge-design-summary.md#decision-d49) 与 [D50](campus-judge-design-summary.md#decision-d50)，现有成绩与榜分规则见 [生产设计](campus-judge-production-design.md#grading)。本文描述实现，不代表生产环境已经迁移或部署；实际检查结果由本次交付报告单独记录。

## 工程与数据边界

- `apps/web` 沿用现有页面、编辑器和代码保存流程，提供余额/流水、题目辅助入口、教师内容与规则管理、管理员记账与审计。
- `apps/api/src/modules/luq.module.ts` 使用既有 NestJS 会话、鉴权、CSRF 与响应流程。
- `packages/domain/src/luq-*.mjs` 负责授权、计价、事务和业务规则；`043_luq.sql` 负责唯一约束、不可变快照、追加式账本及与可信判题结果同事务的奖励结算。
- 判题仍由现有独立 worker 和执行器完成。worker 不获得 Luq 表的读写权限，也不持有应用或迁移所有者凭据。奖励由固定可信 schema 的数据库函数/触发器响应现有判题写入，不执行学生代码。

| 数据 | 用途与约束 |
| --- | --- |
| `luq_accounts`、`luq_ledger` | 稳定身份 UUID 的余额及追加式收支；每条流水保存变动、变动后余额、来源、操作者、原因与时间 |
| `luq_initial_grants` | 每个稳定学生身份的一次性初始助学金，保存金额、配置版本和原流水，不能修改或删除 |
| `luq_price_batches` | 批量定价请求与结果，服务端幂等、全批授权、原子提交 |
| `luq_first_ac_claims`、`luq_activity_awards` | 学生与稳定题目、学生与活动的唯一奖励记录 |
| `luq_assistance_entitlements` | 学生＋稳定题目＋辅助类型＋目标语言的永久购买权益 |
| `luq_assistance_contents` | 独立录入、审核、发布且对应题目版本的学生辅助正文 |
| `luq_content_batches` | 参考答案批量审核的追加式请求与结果，绑定操作者、参数和内容快照 |
| `problem_public_statements` | 准确题目版本的已审核公开英文展示及白名单元属性，追加保存，不覆盖原判题版本 |
| `luq_assistance_deliveries` | 服务器提供正文的追加记录；与购买权益分开 |
| `luq_activity_rules`、`luq_assistance_policies`、`luq_setting_versions` | 活动奖励、辅助开放及管理员配置的规则版本 |
| `luq_submission_results`、`luq_paper4_results`、`luq_review_cases` | 初次有效结果及重判差异核查记录 |

所有权益和余额绑定 `identities.id`，不使用用户名、学号文本或登录账号作为学生主键。普通题目稳定键为 `problem:<problemId>`；Paper 4 大题为 `paper4:<sourcePaperId>:<questionKey>`，无来源副本时使用本卷 ID。版本、语言或活动变化不会产生第二份首次 AC 奖或重复购买机会。

## 获取与结算

每个稳定学生身份默认自动获得 **100 Luq 初始助学金**。迁移 044 为现有未归档学生追加流水，不重置原余额；未来新建的学生身份（含未分班、尚未激活账号）在身份创建事务中获得。归档学生在首次恢复时领取。改名、账号激活/换绑、归档后再次恢复、重跑迁移均不重复发放。

管理员可在 `/admin/luq` 修改初始助学金为 0–100000；变更只影响尚未领取的身份，不向已有身份补差额。配置为 0 时仍保存一次性领取记录，不写零金额流水。此项是初始助学金，不是历史积分兑换或历史 AC 补发。

管理员可选择个人、多个班级或跨班级学生发放 Luq，也可带原因追加正负调整。批次先固定适用身份集合，再原子入账；同一请求键重试不重新取当时班级名单、不重复记账。调整不能把余额扣为负数。

默认首次正式 AC 奖励为 **4 Luq**。普通题目须在提交时属于已发布、经管理员审核公开的可计奖版本；Paper 4 须为正式交卷快照的完整大题自动测试 AC。重复提交、换语言、换版本、换活动、重复判题回调不再计奖。样例、自定义运行、单阶段运行、参考答案验证、登录和页面停留不发奖。既有订正流程不覆盖原成绩，且仍受同一稳定题目的一次性资格约束。

教师可为本人负责的作业、限时训练和 Paper 4 活动设置额外 Luq，默认 **0**，每学生每活动至多一次。规则同时指定最低 AC 题数和最低完成/成绩百分比；二者均满足才结算。普通作业采用截止前有效正式提交的逐题最佳结果，限时训练采用首次公布时的截止前最终正式提交结果；Paper 4 使用自动 AC 大题数占比，**不是教师评定的 75 分卷面成绩**。额外奖可与独立的首次 AC 奖叠加，不使用旧积分的速度或少尝试公式。

普通作业、限时训练的规则在草稿阶段设置，发布后冻结。Paper 4 活动为独立副本，须在明确的未来开始时间之前、且尚无答卷时设置；立即开始或无开始时间的活动已经冻结。学生可查看已分配活动的奖励与辅助开放规则，前端显示冻结状态，服务端和数据库均检查冻结边界。

限时训练在成绩首次公布后结算；Paper 4 模拟考试在该学生成绩公布后结算。有效截止基于服务端接收时间、个人截止、活动结束与强制结束时间，客户端倒计时不决定资格。规则、辅助状态及首次 AC 配置在接受提交时保存，重试和后续配置变更不改写该快照。

重判与初次结算分开：结果差异进入 `luq_review_cases`，不因重判自动补发或追回已经入账的 Luq。管理员查看核查记录后，可带明确原因另记调整；不会删除原流水或自动产生负余额。

## 辅助内容、购买与答案联动

首版仅开放两个类型：

| 类型 | 学生内容 | 默认价格 |
| --- | --- | --- |
| `FULL_TRANSLATION` / `zh-CN` | 中文完整题面 | 3 Luq |
| `FULL_SOLUTION` / 空目标语言 | 完整题解与参考代码，可用 Markdown 代码块 | 8 Luq |

内容由获授权教师或管理员人工录入、核对并明确发布，不在学生点击时调用翻译服务。私有参考程序、教师批注、隐藏测试和判题驱动不会自动成为辅助内容。发布前必须确认正文面向学生且不含私有材料；教师负责核对译文、解释和参考代码的准确性及来源。已发布正文不可直接覆盖，修订须随新的题目版本重新审核；需要停止开放时使用禁用规则。

### Paper 4 翻译与题解审核入口

教师端侧栏「Luq 助学管理」（`/teacher/luq`）中，管理对象选择「Paper 4 试卷」，选择试卷与大题，再在「内容录入与发布」选择「完整题解与参考代码」。录入中文思路和带 `python` 标记的完整代码块，依次保存草稿、预览，核对版本、准确性和公开范围，勾选审核确认后点击「审核并发布」。草稿不能供学生购买。作者、审核账号和发布时间保留在内容记录与审计流水中；目前允许有管理权限的作者自行审核，并非强制双人审批。

中文题面使用同一流程，类型选择「中文完整题面」，目标语言为 `zh-CN`。核对原题结构、小问、分值、输入输出、变量名、代码和文件名，必要时对照原卷 PDF 补齐文本提取遗漏的公开图表；不得引用隐藏测试或私有批注。保存草稿、预览、明确审核发布后，学生才可解锁。

同页的辅助规则独立控制禁用、付费、免费和开放时间；管理员在 `/admin/luq` 配置全校默认价格。学生在 Paper 4 答题页的「Solution / 参考答案」入口确认价格和奖励影响后查看。按**大题**解锁，不是一次购买整卷，也不是按小问重复收费。代码主题在代码框上方，默认 GitHub Dark；中文说明使用页面配色，复制操作仅针对代码块。

2026-10-20 按明确授权在本地 3000 整理、审核并发布 32 套试卷的 96 道题解，见[本地发布核验记录](paper4-luq-solutions-2026-10-20.md)。这是一次受控内容发布，不属于迁移时自动公开参考答案；其他部署仍需单独授权同步和审核。

### 批量设置解锁价格

教师端 Paper 4 列表勾选多套试卷后点击「Luq 价格」，或进入 `/teacher/luq` 的「批量解锁价格」。支持普通题目和 Paper 4 自由练习试卷，搜索后全选、分别勾选翻译/题解，并设置 0–1000 Luq；留空恢复全校默认价。Paper 4 的价格应用于每道大题，永久权益仍按大题区分。活动副本继承来源试卷价格；活动辅助开放规则保持单独控制。

批量操作先校验全部目标管理权限，再在同一事务追加各类型规则版本与批次审计；任一目标无权限则整批不写入。相同请求重试返回原结果，不重复创建版本。改价保留原开放方式和时间，不公开草稿，不重收已购买学生的费用；已取得但尚未确认的旧报价价格发生变化时需重新确认。0 Luq 按免费提供处理，不产生永久购买权益，考核禁用仍优先。

设置价格不会发布内容。保存结果展示本次保存时当前版本的已发布、草稿、未录入、已撤回数量，并提供对应内容类型的录入审核入口；只返回状态元数据，不返回正文。课程或活动固定的旧版本仍须独立审核。2026-10-20 补齐本地「Python 语法与综合实践」22 道配套题解并验证课程入口，见[课程题解修复与实测记录](luq-course-solutions-2026-10-20.md)。

### 批量审核发布参考答案

教师端 `/teacher/luq?mode=review` 的「批量审核题解」展示普通题目和 Paper 4 大题的已发布、待审核、缺少内容与已撤回状态。普通题选当前公开版本，尚未发布的题目选最新草稿；Paper 4 选当前版本。支持搜索、状态筛选、全选筛选内草稿、正文预览及一次确认发布多项，缺少内容的题目提供准确版本的录入入口。预览保留代码主题选择，默认 GitHub Dark。

服务端仅批量发布明确审核过的既有 `FULL_SOLUTION` 草稿，不自动复制私有参考代码。内容摘要绑定预览与发布，草稿被修改或任一项失去管理权限时整批拒绝；行锁、幂等请求表与逐项审计防止并发重复发布。批量发布不改变解锁价格、学生余额、购买权益和考核限制，详见[批量审核说明与实测记录](luq-batch-review-2026-10-20.md)。

### 普通题公开英文与中文辅助内容

普通题的公开英文展示独立绑定准确版本，原题、参考程序和判题输入继续保留在原版本中。迁移 047 新增追加式 `problem_public_statements`，不自动翻译、回填或公开题目。维护者核对原文与白名单元属性后，通过受鉴权接口明确审核；相同快照可重试，不同正文不能覆盖已发布记录。学生响应采用对应版本的展示内容，课程及活动固定版本不会被悄悄替换，已有题目权限继续生效。

中文题面单独作为 `FULL_TRANSLATION / zh-CN` 审核发布，题解继续使用 `FULL_SOLUTION`。学生可见元属性仅包括学习目标、参数说明、返回类型、输入输出和难度；教师私有字段、任意导入附加属性、隐藏测试和参考代码不会因英文展示自动公开。本轮本地内容整理范围为 80 题英文展示、80 份中文翻译和 58 份缺失题解，另补齐 4 个历史版本的对应内容以保留旧课程引用，原 22 份已发布课程题解保留。已采用英文展示的稳定题目不能从未覆盖旧版回退读取中文原文，需在补齐历史内容的同时验证此访问边界。实际进度、Workshop/Decimal 审阅说明与本轮验证记录见[普通题内容整理记录](luq-ordinary-content-2026-10-20.md)。

每次提供正文都重新检查题目权限、活动参与资格、辅助模式和开放时间。模式为禁用、付费或免费。全校普通练习默认付费；未公布结果的限时考核、Paper 4 模拟考试默认禁用。请求不带活动上下文，也会检查该学生已分配的相关活动限制；旧版本、课程链接、自由练习或已有权益不能绕过正在生效的限制。某一任务免费开放只允许该上下文读取，不自动授予永久权益。管理员把价格设为 0 时按免费提供处理，也不制造零额消费流水。

交易分为三个步骤：

1. `POST /api/v1/luq/assistance/quote` 仅返回类型、价格、余额、扣后余额、是否开放及正文标识，**不返回正文**。
2. 学生明确确认后调用 `/unlock`，服务端重新计价、校验确认的价格和正文标识，在同一事务写扣费与永久权益。余额不足失败，恰好够用成功；没有已发布正文不扣费。同一权益重复请求、并发请求或跨设备重试只扣一次。
3. `/provide` 再次鉴权，读取获授权的版本正文并记录服务器提供事件。已解锁的同类型内容免费重看；旧权益可用于新的已发布版本，但不会把旧版答案错当成新版答案。与原卷完全相同的 Paper 4 活动副本可使用原版已审核内容；有改动的副本必须另有对应版本内容。

购买后取消查看，不产生答案提供记录。中文翻译不影响首次 AC Luq。完整题解或参考代码在提交接收之前已经由本站提供时，该次提交仍照常判题、计成绩和既有积分，但不取得本题首次 AC Luq；免费的完整答案使用相同规则。先提交、后查看、仍在等待判题的提交保留原快照。已获得的奖励不会因之后查看答案被追回。

实时的答案辅助 AC **不占用首次奖励槽位**，避免较早提交、尚未判完的独立作答被较晚完成的辅助 AC 抢先排除。后续提交仍会记录已经提供答案，因此不能通过重新提交消除辅助状态。挑战活动默认排除答案辅助提交；教师只可在学习或订正类型中明确允许此类提交参与额外活动奖励。这些状态只决定 Luq 资格，不称为作弊，也不改写 AC、成绩或榜分。

“提供记录”表示服务器通过授权接口提供了正文，不证明学生阅读、理解或使用了它。这里不依赖前端自报“看过答案”。购买权益与提供事件分别记账，未解锁、取消或获取前校验失败不会写入提供事件。

## 配置、接口与权限

管理员 Luq 页面管理以下数值，更新保留配置版本：初始助学金默认 100（0–100000）、首次 AC 奖励默认 4（0–100），翻译默认 3、题解默认 8（均为 0–1000），每学生每活动额外奖励上限默认 40（0–1000）。活动规则设置时受当时额度限制，之后调低额度不追改已冻结活动。奖励设为 0 表示不发对应 Luq，不改变已有成绩和积分。

| 入口 | 权限与用途 |
| --- | --- |
| `GET /luq/me` | 学生本人余额和分页流水 |
| `GET /luq/ledger`、`GET /luq/reviews` | 管理员流水与重判核查；流水支持身份筛选 |
| `POST /luq/grants`、`/adjustments`、`/refunds` | 管理员带原因记账；退款关联原消费，全额最多一次，保留购买权益 |
| `GET/PATCH /luq/settings` | 登录用户读取价格；仅管理员修改 |
| `GET/POST /luq/contents`、`POST /luq/contents/:id/publish` | 内容维护者录入及审核发布；学生不得调用来读取正文 |
| `GET/POST /luq/public-statements` | 维护者读取原题快照并明确审核发布准确版本的公开英文展示；元属性白名单、摘要核验、追加保存 |
| `GET /luq/contents/review`、`POST /luq/contents/batch-publish` | 教师/管理员查看可管理范围的参考答案状态；明确审核后原子发布 1–500 项，快照校验、幂等重试，不返回正文 |
| `GET/POST /luq/policies`、`GET/POST /luq/reward-rules` | 负责教师/管理员设置；学生只可读取已分配活动的规则 |
| `POST /luq/policies/batch-prices` | 教师/管理员对 1–500 个有权管理的普通题目或自由练习试卷批量定价；独立翻译/题解，幂等请求键，全批原子提交 |
| `GET /luq/usage` | 负责教师/管理员查看所管题目、试卷或活动最近的正文提供记录 |

上表路径均以 `/api/v1` 为前缀。所有资金计算与权限判断在服务端完成；活动名单、教师所有权、版本和报价不能由客户端声明替代。API 使用既有会话和 CSRF 保护，响应 `Cache-Control: no-store`。正文不进入报价、一般题目响应、SSR、预加载、公共下载或共享缓存。旧 Paper 4 私有参考答案接口对学生关闭；教师仍可在其管理范围按冻结版本查看私有参考材料。

余额、流水和对应来源/权益原子提交。账户锁、身份辅助锁、稳定来源唯一约束、请求键和不可变记录共同防止重复发放、重复扣费与负余额。退款按原消费唯一去重。应用角色没有直接改写账户余额、账本、奖励观察结果的权限；流水、权益、规则版本和提供记录禁止修改或删除。判题结果写入和 Luq 结算在同一数据库事务中完成，失败时一并回滚，由现有任务租约重试，不另建不可靠的前端奖励回调。

## 迁移与运行

本轮仅按用户授权更新本地 3000，未推送或操作 rslab。其他环境升级应沿用已有部署流程：

1. 对现有数据库做一致性备份，保留卷、学生代码、任务、成绩和身份数据。
2. 使用迁移所有者运行 `packages/domain/src/migrate.mjs`，依次应用尚未执行的 043–047 迁移；044 会追加现有学生初始助学金（默认 100），045 增加可选题目价格与批次记录，046 增加参考答案批量审核的追加式请求记录，047 增加准确版本的公开英文展示表且不自动回填内容；随后运行同一版本的 `packages/domain/grants.mjs`。两者必须一起升级，不能只迁移表而沿用旧授权脚本。现有 Compose 的 `migrate` 服务已按此顺序执行。
3. 使用匹配的 API/Web/worker 版本，核对受限运行角色及迁移成功状态。迁移所有者凭据只用于迁移，不给 API、worker 或执行器。
4. 管理员确认价格和教师额度；教师逐版本审核需要开放的内容。旧题目的 hints/editorial 和 Paper 4 私有 reference_solutions 不自动迁为已发布辅助正文；升级后需要先录入、审核才能从学生辅助入口取得内容。没有审核内容的入口显示不可用，不收费。

迁移建立启用边界和历史首次资格记录，**不创建历史奖励流水、不兑换旧积分、不补发历史成绩**。043 建账余额为 0；后续 044 另行追加一次性初始助学金，未改写历史积分或历史成果。已存在的普通正式 AC、历史判题 AC 证据及 Paper 4 正式大题 AC 被标记为历史资格已使用；既有判题结果也记录为观察基线。迁移前接受、迁移后才完成的提交不因处理延迟成为新奖励。迁移前已发布的活动不补配奖励规则，默认额外奖励 0。

不能用重置数据库、重跑演示种子或删除 Luq 表来回退。回滚应用前应评估旧版本会否恢复无保护的答案接口；已产生的余额、权益、流水和提供记录必须整体保留并以新迁移修复。

## 首版限制与验证口径

- 首版人工录入译文/题解；没有逐次实时翻译，也没有后台 AI 生成工作流。扩展提示类型须增加相应服务端规则和审核流程，不预留无功能按钮。
- 迁移前系统没有完整的“答案已提供”记录，无法还原未留痕的历史查看行为；新启用后的联动以可信提供记录和提交快照为准，历史 AC 则已排除再次领奖。
- 提供记录随正文响应的业务事务提交，不是浏览器收包确认。若提交后网络中断导致响应丢失，服务端无法证明浏览器实际收到或阅读了正文；这类争议需结合提供记录核查，不能把记录解释成“已阅读”。购买未调用提供接口、取消确认或提供前校验失败均不产生记录。
- 教师使用记录当前返回最近 500 条，管理员重判核查页返回最近 200 条；收支流水分页。历史记录仍在数据库中，不因展示窗口删除。
- 重判核查是可审计列表，人工调整有独立原因和流水；不自动判断哪一方正确，也不自动追扣。
- 发布审核是维护者的明确动作，不等同于机器证明内容正确。私有参考程序不会随升级自动复制到可消费内容。

验证应在独立测试数据库中进行，不能连接学生正在使用的数据库。检查命令为 `npm run typecheck`、`npm run lint`、`npm run build`、`npm test`；数据库/鉴权检查包括 `luq-ledger.integration.test.mjs`、`luq-assistance.integration.test.mjs`、`luq-runtime-roles.integration.test.mjs`、`paper4-solutions.integration.test.mjs` 和 API `luq-http.integration.test.mjs`，并需回归原有积分、限时成绩、Paper 4 正式判题及隔离相关测试。
