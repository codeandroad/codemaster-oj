# CodeMaster 多校工作区与公开练习

日期 2026-11-06，更新至 2026-11-07（064／065）。目标是在同一个站点提供一个登录入口、独立的学校工作区和全站公开练习区。

## 账号、学校与内容

账号代表登录主体。学校成员关系按学校授予角色，学校身份档案用于学号、班级和成绩。用户可以没有学校身份，也可以在不同学校获得不同角色。学校管理员移除成员只撤销本校权限，停用全站登录由独立的平台权限控制。个人注册已开放，邮箱选填；邮箱验证、自助找回密码及账号合并尚未实现，不能把当前注册页视作这些能力已经上线。已登录账号可在个人资料修改密码。新学校既可通过邀请码加入后显式关联档案，也可使用本校管理员签发的单次激活码认领已有档案；激活必须提供学校标识、身份类型、学工号、姓名和码，不按跨校同名同号自动匹配。

现有账号记录同时承担凭据和历史操作者的职责，提交、题目及课程仍引用这些记录。首期复用现有登录账号作为成员键。个人注册复用现有账号与会话表，使用 `identities.kind=personal` 保存独立登录身份，不授予旧学校角色；校内业务身份另由学校档案显式关联。历史账号和身份 ID 不变，不通过修改已有外键合并历史。新学校档案的编号约束为学校、身份类型和编号的组合。同一用户跨校切换时，后端根据请求中的学校 ID 和会话核对成员权限。

| 内容范围 | 可访问者 | 发布责任 |
| --- | --- | --- |
| 全站公开 | 已登录的个人用户和学校用户 | 平台按具体题目版本和课程发布版本审批 |
| 本校可见 | 对应学校的有效成员 | 本校有发布权限的人员 |
| 班级或活动 | 有明确授权的班级成员或参与者 | 相应学校、班级或活动的负责人 |
| 私有草稿 | 资源所有者与显式协作者 | 相应工作区内的作者和授权人员 |

当前全站公开目录只收录经平台显式审核的新学校普通题目和全校课程，旧学校的“校内公开”不会自动升级为全站公开。公开提交使用独立练习上下文，不发放旧学校积分或 Luq。后续公开课关联练习、学校引用公开题布置作业、Paper 4 及题解开放仍须分别实现授权与版本边界，不能依靠现有全局角色绕过。

## 本阶段已实现

截至迁移 065，已在隔离本地试点实现：

- 个人注册、明确学校范围的已有身份激活、全角色邀请码加入，以及按当前学校授权的切换入口。
- 原校历史归属与平台学校治理；新学校的成员邀请、校内档案、班级名单、课程阅读与进度。
- 学校中英文名称、默认学校设置，以及沿用原系统侧栏、主题和控件的统一工作区；个人资料与个人设置独立，复用原 `ProfileEditor`。
- 新学校普通题库、参考程序验证、发布及真实隔离判题；经平台准确版本审核的全站公开课程和普通练习。
- 新学校班级卡片与名单并排布局；教师本班学生增删和导入、班级编辑／归档／恢复；管理员分配教师；学生 Home、My classes 与本人 Submissions，以及紧凑校内题库／题目表格。

新学校尚未接入原系统的作业、限时训练、Paper 4、校内奖学金、排行榜、教学报告及课程配套题链接／练习进度联动，不显示这些功能的空入口。原校业务继续使用原有入口与数据；当前只对齐已实现模块，不能声称全部侧栏入口或业务已完成多租户改造。各阶段的迁移与边界见下文；本轮只面向本地人工核验。

## 学校成员与邀请（052，含 062 扩展）

迁移 052 新增学校、试点成员、邀请和学校审计四张表。原有学校以固定工作区出现，055 明确归属为“天行创世纪学校”，058 增加可配置的中英文名称。新学校成员关系独立存放，学校角色仅授权对应学校接口；旧学校业务仍使用原角色和明确的原校归属校验。

首任试点学校管理员由持迁移凭据的部署维护者指定为现有有效账号。用相同标识、名称和首任管理员重试会返回已存在的学校。056 已增加独立的平台管理员能力和学校治理页面，后续学校可由该入口开通。

```sh
cd packages/domain
node src/migrate.mjs
node grants.mjs
node src/provision-school.mjs school-alpha "Alpha School" existing-username
```

以上命令读取部署环境注入的 `DATABASE_URL`。试点阶段在隔离数据库运行这组命令。接口使用已有会话、Origin 校验和 CSRF 防护。

| 接口 | 作用 |
| --- | --- |
| `GET /api/v1/schools` | 返回自己的有效学校与角色 |
| `GET /api/v1/schools/:schoolId/members?page=1` | 本校管理员分页查看成员 |
| `POST /api/v1/schools/:schoolId/invitations` | 本校管理员签发 `student`、`teacher` 或 `school_admin` 邀请（管理员邀请自 062 起） |
| `POST /api/v1/school-invitations/accept` | 已登录用户用 `{"token":"…"}` 领取邀请 |
| `DELETE /api/v1/schools/:schoolId/members/:accountId` | 本校管理员撤销一名师生的试点成员关系 |

邀请由持码的登录用户领取，有效期 7 天，只存摘要。领取、审计和成员写入同事务提交。每校最多保留 100 个待领取的有效邀请。首任管理员由维护者或平台管理入口任命；062 允许本校管理员签发本校管理员邀请，不授予全站权限。目录仅返回管理所需的姓名、账号 ID、角色和加入时间。学校审计使用独立表，旧的全站审计查询无法读取这些事件。判题 worker 角色没有四张新表的访问权限。

## 校内档案和班级试点

迁移 053 增加独立的学校档案、班级和班级名单。编号以学校及档案类型为范围。同一账号在一所学校只能关联一个档案，在不同学校可关联各自的档案。档案可以先建后关联，管理员只能选择本校已加入且角色相符的账号。复合外键阻止跨校名单关联及角色不匹配的账号关联。

学校管理员可创建师生档案、关联或解除关联、建立班级并增删名单、分配负责教师。064 阶段新增教师本班写入：已关联本校教师档案的教师可创建班级并自动成为负责教师，只能编辑、归档／恢复本人负责班级，添加、移除或导入其中的学生，不能分配教师或修改全校身份目录。学生仅能读取自己所属的未归档班级和同班学生名单，名单只投影校内身份 ID、类型和姓名，不返回学号、账号、邮箱或激活信息。移除学校成员时，同一事务解除本校档案的账号关联，保留档案及班级名单。重新加入后需要重新关联，原有教师权限不会自动恢复。

| 接口（相对于 `/api/v1/schools/:schoolId`） | 作用 |
| --- | --- |
| `GET /identities?page=1&kind=student&q=...` | 分页读取档案，可按类型、姓名或编号过滤 |
| `POST /identities` | 新建学生或教师档案，可同时关联本校成员 |
| `PATCH /identities/:identityId/account` | 显式关联账号，或用 `accountId: null` 解除关联；界面同时提交预期的原账号 ID，防止旧页面解除已变更的关联 |
| `GET /members?role=teacher&unlinked=true` | 分页列出符合角色且尚未关联的本校成员 |
| `GET /classes?page=1`、`POST /classes` | 列出有权访问的班级、新建本校班级 |
| `PATCH /classes/:classId`、`POST /classes/:classId/archive`、`POST /classes/:classId/restore` | 校内管理员或负责教师带 `expectedRevision` 修改班级／归档／恢复，保留名单 |
| `GET /classes/:classId/roster`、`POST /classes/:classId/roster` | 分页查看名单，按档案 ID 添加人员 |
| `GET /classes/:classId/candidates` | 当前有权管理的班级候选名单；教师只能选择学生 |
| `DELETE /classes/:classId/roster/:identityId` | 从班级移除档案，不删除档案 |

当前以现有登录账号为成员键。055 完成历史学校归属，059 增加个人注册。学校管理员只管理本校关联，不获得重置全站账号密码的权限。原校题库与作业仍在原有工作区；057 为新学校开放课程编排与阅读，060 增加独立普通题库与判题。

## 批量导入校内档案

学校管理员可从「身份档案 → 导入身份」导入学生或教师，也可从班级名单进入「导入名单」；负责教师只能在本班名单内导入学生，不能改为教师类型或其他班级。CSV 与 XLSX 在浏览器解析，每批不超过 500 行、文件不超过 2 MB；编号和姓名是必填项，编号按文本处理以保留前导零。下载的 CSV 模板只含合成示例。可选本校已有班级，导入时一次性补入名单；不自动建立班级、登录账号或账号关联，不发放奖学金，也不修改历史成绩。

服务端按本校、身份类型、编号核对。已有相同姓名的档案复用；文件中的完全相同行跳过。同编号出现不同姓名或无效字段时，整批禁止确认，不跳过冲突后偷偷导入其余行。界面按新增、已存在、重复、冲突、无效显示逐行预览及统计。

| 接口（相对于 `/api/v1/schools/:schoolId`） | 作用 |
| --- | --- |
| `POST /identity-imports/preview` | 接收 `kind`、`rows: [{number,name}]` 与可选 `classId`，只读核验并返回预览 |
| `POST /identity-imports/commit` | 携带同一输入及 `previewToken`，原子创建缺失档案、补齐名单、审计并记录批次结果 |

预览凭据由服务器签名，绑定操作账号、学校、输入摘要、已有档案／账号关联／班级名单快照，15 分钟有效。不包含姓名或编号。确认及精确重试时重新验证当前校内角色和本班管理权限、CSRF、签名和快照；快照变化或过期需重新预览。所有相关管理写入使用同一学校事务锁，预览使用共享锁；先取得学校锁再核实成员，避免等待撤权期间持有目标成员锁。班级归档后不接受新的导入，已成功且输入完全相同的请求可在当前管理权限有效时返回原汇总结果。

迁移 054 的 `school_identity_imports` 只保存批次、学校、操作账号／班级、请求与凭据摘要及汇总计数，不保存上传文件或逐行名单。确认事务包括档案、名单、逐项审计、批次审计与幂等结果。网络失败后以同一凭据重试返回原结果；已完成的精确请求在凭据过期后仍可重试，但仍检查当前权限。不同输入、学校或账号不能复用凭据。应用角色仅能读取及追加批次，不可修改或删除；worker 没有新增表权限。班级、账号和档案关联仍由复合外键限制在本校。

## 当前学校与切换

平台管理员普通登录进入 `/platform`，不需要加入学校。其他账号按有效服务端默认学校、浏览器学校偏好和有效角色依次确定落点；没有学校的个人账号进入 `/practice`。Logo 下显示当前学校的中英文名称，按界面语言优先选择，缺少时回退到另一名称。主区域只呈现本校已实现业务：新校教师／管理员有首页、班级、题库和课程，管理员另有身份、成员邀请和判题服务；学生有首页、题目、课程、我的班级和提交记录。

切换学校是低频操作，统一在头像菜单 → Settings → Schools 中列出已加入学校，提供 Open、默认学校和明确的加入邀请操作。学校名称行打开配置窗口；只有对应学校管理员可改名。School settings 不占独立侧栏位置，普通登录不自动弹出加入窗口；邀请意图只定位到设置中的学校区域。个人资料由头像菜单单独进入并复用原 `ProfileEditor`，不再放在设置页底部；平台、新校、自由区均保留所在工作区导航。

浏览器仅按账号保存学校 UUID；选择本身不授予权限，每次加载以服务器当前成员列表为准。已失效的偏好回退到有效学校，切换账号／学校／角色时重建校内页面，避免旧名单残留。其他标签页的选择不强制改变当前页面。邀请码不持久化：本次页面会话内按学校暂存新签发代码，切换后可返回查看；签发中的学校切换、功能切换和退出均禁用，避免丢失响应。已打开的建档／名单／导入窗口仍使用模态焦点限制。

原学校保留明确的原工作区入口；新学校题库和课程使用已实现的独立校内模型，未完成的活动模块不出现在导航中。新学校和自由区的头像菜单不显示旧学校角色快捷项；直接进入原校书签时同步记录实际原校上下文，避免设置入口跳回另一学校。

## 接入教学与公开区的顺序

1. **隔离身份和校内管理。** 新增全局登录主体与校内档案关联。将名单、班级、导入和重置凭据接入工作区授权，学校成员导入按本校编号去重。先迁移既有学校的归属，逐步验证所有外键，再为第二所学校启用这些功能。
2. **隔离教学资源和活动。** 题库、课程、作业、计时训练和 Paper 4 绑定学校。通过复合外键限制成员、班级与活动的组合，公开题目的跨校引用使用单独的发布授权。用统一的授权入口覆盖详情、搜索、导出、通知、附件和异步任务。对学校数据逐表加入行级安全，应用角色使用非所有者权限，数据库连接池的学校上下文随事务清除。
3. **上线公开练习。** 增加邮箱验证和个人注册、公开目录与发布审核。公开提交拥有自己的练习上下文和配额。普通题与 Paper 4 都经现有独立判题服务执行，对公开流量限速和限制并发，为校内考试保留容量。
4. **迁移和上线。** 分别在 tx99 和 ali99 的备份恢复库验证学校归属、角色与既有成绩。若后续合并站点，先审核两站独立变化，建立账号、学校与资源 ID 对照。重复账号不能仅凭同名或同学号自动关联，成绩与 Luq 流水也不能覆盖合并。按工作区逐步切换，每步留有应用回退方案和可核对的迁移记录。

每开放一类学校功能，都需用真实数据库验证 A 校管理员无法读写 B 校资源，覆盖直接 ID、跨校关联、列表、导出及后台任务。公开注册还需验证个人账号与校内数据的边界、公开版本撤回、判题回压和已有历史读取。

## 历史学校归属与平台治理（055／056）

原系统以固定学校 UUID 归入“天行创世纪学校”。班级、题库、课程、作业、限时训练、Paper 4 与资料七个业务根表新增 `school_id`；题目、版本、活动参与者、提交、成绩及 Luq 依原外键追溯，不复制记录、不重新开户、不重发奖励。原身份和全部历史账号绑定分别保存明确归属映射，原 `account_roles` 的多角色语义保留。无原角色的多校试点登录凭据不因此加入天行学校。事务提交时的受限触发器维护后续原校建档、认领和换绑归属。

平台管理员与学校管理员分离。`platform_admins` 只经持迁移凭据的维护命令显式授予，现有 `admin` 不自动升为平台管理员。平台入口 `/platform` 提供学校汇总、开通、改名及管理员任命，不授予题目答案、学生成绩或 Luq 管理权限。教师或学生可通过附加的 `school_administrators` 权限兼任本校管理员，原档案身份和班级名单不会改变。所有治理写入记录审计，学校管理员不得修改、停用、解绑或重置已授权的平台管理员账号。

```sh
# 在目标环境完成迁移与角色授权后，显式指定一个现有有效登录账号。
node packages/domain/src/provision-platform-admin.mjs existing-username
```

056 时点的平台账号仅用于学校治理；058–061 另增加明确的平台公开内容审核能力，日常教学仍以当前学校为主体。迁移器维护学校归属映射，应用只读映射和平台授权，worker 对这五张新增管理表没有权限。创建学校用唯一学校标识幂等，任命用学校与账号唯一约束，改名使用原名称校验避免覆盖并发变更。

范围限制（055／056 时点）：当时新学校教学尚未开放；后续 057 增加课程，060 增加普通题库及判题，活动与 Luq 仍待接入。七个旧业务根表暂时通过数据库约束只能属于天行学校，避免新学校误写旧业务。原校管理员任命仍由原角色管理，平台页面不显示该任命按钮；本轮不提供尚未贯穿全部旧接口的停校功能。自由个人注册及全站公开课程在当时仍是后续工作，现由 059／061 提供初版；这仍不是全面完成的生产多租户系统。


## 校内课程与原校入口隔离（057）

在当前学校中，管理员可管理本校全部课程，教师可创建和管理本人课程。课程由简介和有序 Markdown 章节组成，可面向全校学生，或选择本校多个班级；教师只能选择本人负责的班级。057 阶段仅提供课程内容阅读与进度；060 虽已开放普通题库，但课程与练习关联、练习完成进度及作业仍待接入，不以旧全局角色代替校内授权。

学校课程与旧 `learning_paths` 并存。迁移 057 新增课程草稿、草稿班级、发布快照、发布班级和阅读进度五张表，复合外键约束学校、课程、班级和身份。原校仍使用已有课程与章节关联，迁移不复制或改写原课程、成绩、提交及 Luq。新学校接口拒绝原学校 UUID，以免出现两套原校课程入口。

| 接口（相对于 `/api/v1/schools/:schoolId`） | 作用 |
| --- | --- |
| `GET /courses?page=1&q=...` | 每页 50 门，仅返回有权访问的课程；学生搜索已发布版本 |
| `POST /courses` | 以 `requestId` 创建草稿，输入为标题、简介、章节、有序章节 UUID、开放范围与班级 ID |
| `GET /courses/:id`、`PATCH /courses/:id` | 阅读或修改有权访问的课程；修改带 `expectedRevision` |
| `POST /courses/:id/publish`、`POST /courses/:id/unpublish` | 明确发布／下架，带 `expectedRevision`，同事务审计 |
| `POST /courses/:id/chapters/:chapterId/read` | 学生用 `read` 布尔值和所读版本 `expectedRevision` 更新本人阅读进度 |

草稿编辑不影响已发布的正文、标题和可见班级。发布把这些字段一起保存为不可覆盖的快照；下架立即停止学生列表、详情和进度写入，不删除既有进度。所有写入核对版本以防并发覆盖；创建按学校、作者和请求 UUID 去重，同键不同输入报冲突。发布／下架重试使用旧版本时返回冲突，须刷新确认服务器状态。

学生仅能阅读当前已发布且符合受众的快照。未分班学生可阅读全校课程；未关联本校学生档案的有效学生成员也可阅读，但不能记进度。进度绑定稳定学校身份与章节 UUID，纯粹调整章节顺序不会丢进度；正文或标题变更则按新内容重新阅读。服务端核对提交的发布版本，旧页面不能把新发布的内容误记为已读。账号解除关联后不能再写原档案的进度。

五张表均启用并强制 RLS。域业务先验证会话、本校有效成员与角色，再在同一事务中使用 `set_config('campus.school_id', ..., true)`；事务提交／回滚后上下文清空。没有上下文的应用角色读不到课程，跨校写入由数据库拒绝。应用角色只能追加发布快照，worker 对五张表无任何权限；执行器不变。057 阶段的平台学校统计只返回数量，不返回章节正文；061 新增的独立公开课程审核接口在平台授权后返回待审核的已发布章节，不能通过学校统计接口代替内容授权。

旧业务接口在统一 `prepareRequest` 中要求 `legacy_school_account_ownership`。新学校和仅平台账号不能通过猜测旧题目、课程、作业、提交、Luq 或在线名单 ID 访问原校数据。只有明确列举的登录、自身资料、公开站点配置、学校及平台入口例外。原校账号继续通过旧接口原有的角色和资源校验；拥有两个学校成员资格不扩大其原校角色。旧题库的 school 可见性仍只代表原校，不是平台公开发布。此保护不等于所有旧模块已改造成多租户，个人注册已由 059 实现，旧教学模块的进一步学校化仍是后续范围。

界面保留当前学校为中心的紧凑导航。课程列表有搜索、分页和状态；编辑窗口保留失败输入及未保存离开确认；发布和下架单独确认。学生章节阅读提供上一章／下一章及已读切换，不引入题目或判题占位按钮。


## 学校名称与统一入口（058）

`schools` 增加 `name_zh`、`name_en` 和 `settings_revision`。本校管理员从“学校设置”编辑名称；至少一项非空，每项不超过 100 字符。`GET/PATCH /api/v1/schools/:schoolId/settings` 返回或保存 `nameZh`、`nameEn` 与 `revision`，保存必须提供 `expectedRevision`。同事务行锁、版本核对和审计防止并发覆盖。原校管理员沿用原 `admin` 与归属授权，其名称同时兼容原站点配置；新学校管理员不能修改原校名称。

登录、注册及激活页继续使用原来的浅色布局和相同表单位置。公开 Logo 下显示“编程学习与实践 / Coding, learning & practice”，不再显示某一学校的名字。学校工作区、自由区与原业务复用 `WorkspaceFrame` 的紧凑侧栏和导航；默认界面英文，中文由用户显式设置。界面语言不会改变受保护题面内容。

## 个人注册与账号自助（059）

`POST /api/v1/auth/register-personal` 接收 `username`、`password`、`displayName` 和可选 `email`，成功后建立会话。用户名统一为小写，使用 3–40 位字母数字、下划线、点或短横线，首位为字母数字；密码为 8–128 位。注册不接受角色、学校或身份类型授权参数。用户名事务锁与数据库唯一约束防止并发重复注册；身份、账号、会话及审计原子提交。

个人登录身份使用 `identities.kind=personal`，不写旧 `account_roles`、原校归属或 Luq 初始奖励。加入学校依赖有效邀请，校内档案仍需显式关联。已有原校学生、教师和管理员同样可以接受其他学校的邀请，原角色不会扩大到新学校。062 增加 `school_admin` 邀请，仍只授予本校权限；邀请领取时重新检查签发者权限并保留审计，不授予平台权限。

`/register` 是个人注册；`/activate` 在 065 后按明确学校范围核验已有身份；`/login` 提供这两个入口和邀请码加入入口。`/schools?join=1` 只表达前往设置学校区域的意图，不自动弹窗，邀请码本身不进 URL。`/practice/profile` 提供头像、昵称、介绍、选填邮箱和修改密码，沿用原 `ProfileEditor`、`auth/profile`、当前会话与 CSRF 校验；`/practice/settings` 保留外观、语言和学校设置。个人账号暂不具备邮件验证、自助找回、账号合并或自行创建学校能力。

## 普通题库与隔离判题（060）

新学校题库、题目草稿、不可覆盖的题目版本、判题任务和全站发布授权使用独立表。学校与资源关系由复合外键约束，资源读取启用事务内学校上下文与强制 RLS。学校管理员可管理本校题库，教师按所有权管理本人题目；学生只获取已发布且题库未归档的公开定义。学生正文响应不包含参考程序和隐藏测试。

题目可使用标准输入输出或函数接口。参考程序必须经过独立判题验证后才能发布；学生可运行样例、自定义输入或正式提交。作答复用已有 `CodeEditor`、`MathContent` 和 `RunResultPanel`，不另建编辑器。请求以账号和请求 UUID 幂等，队列限制未完成任务与短时提交量；正式隐藏测试仍按现有反馈规则脱敏。

worker 只取得新增判题任务快照的必要读写权限，不读取新增学校目录、课程或公开阅读进度。执行器继续无数据库权限，API/web 不执行学生代码。公开题和校内题提交使用不同的 `access_context`；本阶段新任务不记入原校成绩、排行榜或 Luq。

## 全站公开课程与练习（061）

`/practice` 向已登录的个人用户和学校用户开放，仅列出平台审核过的资源；首页、课程、题目和“我的学校”沿用统一布局。没有内容时展示真实空状态，不自动复制旧题库、旧课程或学生数据。

平台管理员在独立内容审核入口查看具体已发布正文，确认后写入全站发布记录。普通学校管理员不能自行授予全站权限。公开课程只允许审核学校当前已发布的 `accessScope=school` 版本，班级限定课程和草稿不进入公开目录。公开题目同样审核准确的当前发布版本，题解、参考代码和隐藏测试不会因此自动公开。

公开读取必须同时满足：发布授权未撤回、源资源仍上架、授权版本等于源资源当前发布版本。编辑草稿不改变已批准的公开内容；学校发布新版本后暂停旧的全站开放，必须重新审核该准确版本。学校下架或平台撤回后，详情、列表及进度/提交入口都拒绝继续访问。撤回与读取、提交通过锁内校验避免使用等待前的旧授权。

| 接口 | 作用 |
| --- | --- |
| `GET /api/v1/practice/catalog` | 已审核课程和普通题目的目录，不带课程章节正文 |
| `GET /api/v1/practice/courses/:listingId` | 当前获准版本的章节正文和本人阅读进度 |
| `POST /api/v1/practice/courses/:listingId/chapters/:chapterId/read` | 核对实际发布版本后更新本人已读状态 |
| `/api/v1/practice/problems` 及题目详情/提交接口 | 已审核普通题目、样例运行和正式判题 |
| `GET/POST /api/v1/platform/course-publications` | 平台预览准确课程版本并审批 |
| `DELETE /api/v1/platform/course-publications/:listingId` | 撤回全站课程开放，保留进度 |
| `/api/v1/platform/problem-publications` | 平台预览、审核或撤回普通题目 |

公开课程进度绑定账号、发布记录与章节 UUID，使用章节内容摘要避免旧正文的已读状态误用于新内容；账号 RLS 限制只读写本人进度。所有正文接口沿用认证和 `Cache-Control: no-store`。公开练习暂不发旧积分或 Luq，也没有余额或排行榜占位。

本阶段复用了原系统的页面外壳、编辑器和判题隔离机制，但未完全迁移原校功能：新学校作业、限时训练、Paper 4、校内奖学金、教学报告、课程与习题关联及课程练习进度仍是后续工作；公开目录也尚未提供这些功能。064 已提供学生本班名单读取，不能据此声称全部班级资源或活动已迁移。相关真实数据库回归分别位于 `personal-public-http.integration.test.mjs`、`school-settings-http.integration.test.mjs`、`school-practice-http.integration.test.mjs` 与学校/平台授权测试，实际执行结果记录在本地试点说明。

## 本轮界面与校内读取范围（064／065）

新校班级模块沿用原校班级卡片与右侧名单布局，保留紧凑操作区和使用中／已归档筛选。管理员的分配教师入口与教师的学生名单操作分别授权；教师不能通过改 URL 操作未负责的班级。班级归档保留名单及既有记录，学生不能查看归档班级。064 仅增加 `school_classes.archived_at` 和 `revision`，修改时核对版本，避免覆盖并发编辑。

新校学生首页展示真实课程阅读进度、可访问班级与题目、本人最近提交；My classes 只显示本人名单内班级，Submissions 只查询当前学校、当前账号、`access_context=school` 的正式提交。`GET /api/v1/schools/:schoolId/submissions` 按创建时间分页，不返回学生代码、判题 payload、参考程序或隐藏测试。题库和题目改为紧凑表格，沿用既有查看、编辑、验证和发布流程；这些改动不新增跨校数据访问。

## 学校范围内的身份激活（065）

激活页先要求学校标识，再填写学生／教师类型、学号／工号、姓名与单次激活码。不同学校即使同号同名也分别匹配本校既有档案；错误学校、姓名或码统一返回无法认领，不公开候选身份。学校管理员在未关联账号的档案行签发激活码，返回学校名称和标识、本人档案信息、一次性可见的码及到期时间；码不写入 URL、日志或持久前端存储。

`POST /api/v1/schools/:schoolId/identities/:identityId/activation-code` 只允许本校管理员，065 的新表按学校与档案外键保存码摘要、签发者、到期与消费时间。有效期七天，重新签发使旧码失效；核验和注册都会重新验证签发者当前权限。认领与账号创建、对应学校成员关系、档案关联、码消费和审计在同一事务中提交，并发只成功一次。原导入档案 ID、班级名单和课程关系保留；不会给新校账号写旧全局角色或重发旧积分／奖学金。

原校用 `legacy-school` 明确范围，保留原稳定身份及角色流程。兼容旧客户端遗漏 `schoolSlug` 的请求时，仅允许固定原校范围，不搜索其他学校。已有账号仍通过邀请加入后由管理员关联档案，不用激活流程合并两个账号。应用具备必要的激活表读写权限；worker 和执行器不获得身份、班级或激活码访问权。细节和专项测试见[学校激活说明](multischool-identity-activation.md)。

## 课程目录与已有工作区对齐（067）

本节替代 057／061 中课程目录、课程配套题尚未实现的说明。课程页沿用原校封面、分类、简介、章节数、可见范围与状态表格，提供 Courses／Learning resources、Active／Archived、Markdown 导入、编辑、学生预览、归档／恢复与下架。课程属性随发布快照冻结，修改草稿不会直接改变学生当前看到的版本。导入先预览，不能静默导入旧校题目 ID、Paper 4 链接或私有 checkpointAnswer。

067 为 `school_courses` 添加 `properties`、`archived_at`，为发布快照添加 `properties`；新增 `school_learning_resources` 存储本校学习资料。课程资料接口核对本校角色、所有权、关联课程／章节、请求幂等及修订版本，并写审计；六张课程相关表强制 RLS，worker 和执行器无访问权限。学习资料支持私有／校内范围，删除为软删除。归档保留历史记录并阻止学生继续访问，包括全站公开课程入口。

章节练习绑定本校已发布题目的准确版本、明确顺序，学生从章节进入和返回都保留 URL 上下文；正式 AC 联动章节练习进度，样例运行不算完成。校内进度以判题任务保存的学生身份为依据，不能通过后来换绑账号继承另一位学生的 AC。课程章节、班级选择与题目导航支持刷新和浏览器前进／后退；自己的校内提交可进入只读详情。

题目编辑复用原系统表单与代码编辑器，按题面、程序接口、测试数据、参考程序分区，提供逐行增删复制测试与权重校验。当前校内题目模型仅有标准输入输出和函数接口、比较器、资源限制、初始／参考程序；不显示尚未支持的旧校标签、测试启停等字段。

个人菜单统一为 Profile → Settings → Free practice → Leaderboard（已有排行榜的原校角色）→ Sign out。学校切换、加入、默认学校及管理操作集中在 Settings → Schools，平台与原校多角色的额外工作区入口也在设置中。新学校尚无排行榜，不引导用户访问无权读取的原校排行榜。

仍待实施：新学校作业、限时训练、Paper 4、奖学金账本与排行榜、报告、订正本、课程开放时间／先修条件／隐藏直达规则、自动检查点评分。班级当前提供名单与管理，不包含旧校全部班级活动视图；判题服务当前提供本校队列信息。共享布局与新增课程能力不代表上述业务已完成迁移。
