# Campus Judge · 生产设计 v1

> 2026-10-12：已按用户确认的真实校内 OJ 目标完成首期生产实现。已知部署条件：Ubuntu 26.04、4 核 / 8 线程、16GB 内存、Docker，约 200 名学生，课堂同时在线 30–50 人。原型页面继续作为布局与交互依据，不将固定示例当作真实业务数据。实现与本地验收状态、学校上线条件见 [部署文档](campus-judge-deployment.md)。

<a id="scope"></a>
## 1. 范围与交付

教学闭环：管理员建档 → 师生认领账号 → 教师建班、建题与发布作业 → 学生自测、提交 → 真实隔离评测 → 查看结果与订正 → 教师跟进。当前编程语言为 Python 3.12、C++23 和 JavaScript；三种语言均支持标准输入输出题与函数题。学习路径、章节进度、计时训练、教学报告、题库授权和管理端队列/审计均已接入真实数据。

ACSL 编程备考按赛季、组别、Contest 1–4、知识主题与题目来源组织。标签允许多值，不把一个练习活动等同官方比赛。首期不声称覆盖完整 ACSL 短题考试；短题自动评分与官方比赛规则同步列入后续范围。官方参考：[学习资料](https://www.acsl.org/get-started/study-materials)、[FAQ](https://www.acsl.org/about/faq)。题目来源与使用授权由维护教师记录；不自动抓取未公开比赛内容。

CIE 为可选课程分类，不阻碍首期 ACSL 编程练习上线。当前提供校内积分排行榜，不等同 ACSL 官方竞赛名次；首期不提供公开注册、跨校租户或 AI。

## 2. 架构与模式边界

生产系统独立存放于本仓库根目录，前端采用 Next.js App Router / React / TypeScript，API 采用 NestJS / TypeScript。相邻的 `../myoj-prototype/` 仅为独立界面参考仓库，生产构建与运行不读取它。NestJS 的模块、控制器、共享认证 Guard 和业务服务统一完成 HTTP 接入与授权；独立业务核心保留已验证的 PostgreSQL 事务、数据库迁移与评分规则。PostgreSQL 保存业务数据。首期测试与代码作为私有数据库字段保存，备份随数据库一致，不另设对象存储；规模增加后可迁移至私有文件存储。独立判题调度服务通过数据库任务表及事务领取构成可靠队列，避免额外引入消息队列；以后可替换队列实现。

Web 服务不得执行学生代码。执行器使用 go-judge v1.13.2，隔离环境内提供 Python 3.12、Node.js 22 及 Clang 19 + GCC 14 libstdc++；C++ 编译显式采用 `-std=c++23 -stdlib=libstdc++`。worker 仅持有专用受限数据库角色来领取任务、读取代码/测试、写入结果，不能读取账号或修改班级。可信执行器控制器持有必要 Linux namespace/cgroup 权限，学生进程及 C++ 编译进程使用非 root、独立网络与文件系统、系统调用和资源限制；不能以普通子进程替代安全沙箱。

明确区分 prototype 与 production 两种配置：原型保留共享注册/登录的内存表单和手动结果切换；生产共享界面组件调用真实服务，不显示场景切换工具栏，不允许切回原型绕过权限。生产启动缺少数据库、会话密钥或判题配置时失败，不回退成演示成功。原型数据不导入生产库；演示部署显示 Prototype · Sample data，生产不作此标记。

## 3. 身份、账号与权限

身份使用不可变 UUID，学号/工号为可修改业务编号且在身份类型内唯一。班级为多对多成员关系，区分行政班与训练班；成绩关联身份 UUID，账号关联不修改历史。账号使用独立 UUID，用户名规范化后唯一；每条账号记录的身份归属不可更改。已解除绑定的登录凭据可由管理员明确转移到同类型新身份：新建目标账号、保留用户名与密码哈希，停用并归档来源账号，不继承来源管理员权限或邮箱。来源账号与历史成绩、笔记作者、审计及教学内容继续属于原身份。同身份重新认领可恢复其自身教学内容。身份可具有学生和教师角色；管理员为受控系统角色，不通过教师激活码获取。

管理员导入的是身份名单，不直接创建登录账号。首个管理员由仅限服务器操作的初始化命令创建，禁止公开初始化接口；之后由管理员邀请其他管理员。最后一个有效管理员不得被禁用、归档或移除管理角色，该检查与修改在同一事务中完成。

激活码以密码学安全随机数生成，默认有效期 7 天，凭据表只存摘要；单次发放展示明文，之后只能重发。重发立即撤销旧码；教师名单默认仅显示激活状态。教师可在本人负责班级的名单导入中建立新学生身份并取得首次激活码，不能借此取得其他班级已有身份的凭据或建立教师/管理员身份。班级导入为断线重试提供 15 分钟 AES-GCM 加密结果缓存，密钥由会话密钥按用途派生、绑定账号/班级/请求键；到期清除密文，只保留无凭据导入摘要。密钥轮换后不恢复旧码，需管理员重新发放。核对编号、姓名、激活码后，创建账号、绑定身份、消耗激活码在同一事务内完成，并发认领最多成功一次。统一失败提示并限流，避免泄露身份是否存在。

密码采用 Argon2id 存储，允许密码管理器与粘贴，长度 8–128 字符。会话为服务端可撤销会话，Cookie 使用 HttpOnly、Secure、SameSite，并对状态变更实施 CSRF 防护。登录限流、用户名查重、角色授予全部在服务端完成。禁用账号与变更权限即时撤销会话。

正常认领不强制首次改密。忘记密码由管理员核实本人后生成短期一次性重置凭据，由本人设置新密码；重置成功撤销其他会话，不查看或发放旧密码。身份解绑撤销旧账号会话并停用旧账号，保留审计与所有成绩，重发激活码后方可换绑。

| 操作者 | 允许范围 |
| --- | --- |
| 学生 | 自己的提交、订正、被分配活动与获授权题目；不可读取隐藏测试 |
| 教师 | 自己负责班级的成员与活动成绩；获授权题库的维护；不能为自己授予管理员角色 |
| 管理员 | 身份、账号、系统与授权管理；读取学生代码的管理访问须审计 |
| 判题节点 | 当前领取任务所需代码和测试；无交互登录权限 |

每个读取、下载与写入接口均按资源检查权限，路由、请求中的身份 ID 和前端导航不构成授权。提交详情必须检查拥有者或负责教师范围。

## 4. 数据关系与版本

核心实体：Identity、Account、AccountRole、Session、ActivationToken、ResetToken、Class、ClassMember、TeacherClass、ProblemBank、BankPermission、Problem、ProblemVersion、TestCase、ProblemGroup、ProblemGroupMember、Assignment、AssignmentProblem、ActivityParticipant、Submission、JudgeRun、JudgeTask、ReviewEntry、TeacherFeedback、LearningPath、Chapter、TimedPractice、PracticeAttempt、AuditEvent。

外键与唯一约束保证账号认领、用户名、成员关系、分组关系和请求去重。服务端记录创建/修改时间与操作者；所有时间存 UTC，界面显示 Asia/Shanghai。实体采用归档而非删除已有历史引用。

Problem 的稳定 ID 与版本分离。已发布题目版本不可原地修改；题面、接口、限制、比较器、公开样例、正式测试、多语言起始模板及参考解语言均属于版本。修改创建新草稿，校验通过才能发布。活动固定引用题目版本及活动分值，不能静默升级；首期不提供活动题目版本原地替换，需建立新活动。历史提交固定代码、语言、题目版本、活动上下文与运行环境版本；旧提交和旧版本默认 Python，不通过改写历史版本启用新语言。

题库是题目权限边界；分组是引用关系，不改变权限或成绩。跨题库复制需建立新题目并保留来源，不能靠分组移动绕过权限。“未分组”由没有真实分组关联计算。教师创建的题库默认仅作者及获授权教师可维护；只有管理员能将题库设为全校范围。教师向系统校内题库投稿并发布后，版本仍须经管理员审核才进入全校自由练习列表；被明确分配作业或训练的学生仍能访问活动固定的已发布版本。校内公开与榜单资格绑定到具体版本，修订后的新版本重新审核，防止未审核题面或活动题意外公开。管理员将校内题库改为私有或归档前，须先逐版本撤下所有已公开题目；撤下不重算既有榜分。升级前已经公开的版本保持学生访问，榜单资格仍待管理员审核。

<a id="judging"></a>
## 5. 提交与判题契约

Run Samples、Run Custom Input 与 Submit 为不同任务类型。自测不生成正式成绩，不读取隐藏测试；自定义输入无期望输出时仅显示运行状态和公开输出，不显示 AC。所有运行均实施资源与频率限制。代码和输入限制默认各 256 KiB，可由配置降低；超限请求在入队前拒绝。

提交接口接受幂等请求键及语言标识 `python`、`cpp` 或 `javascript`，在同一事务内验证身份、活动窗口、题目版本并写入 Submission 和 JudgeTask；未传语言的旧客户端按 Python 处理。语言属于幂等请求内容，键相同但语言或代码不同返回冲突。返回已接收编号后才视为正式提交；前端点击或本地草稿不算接收。重复请求返回相同编号，断线重试不得产生重复成绩。

状态：Waiting → Judging → AC / WA / CE / RE / TLE / MLE / OLE / System Error。领取使用租约与唯一执行编号，心跳过期可重试；回传仅接受当前租约，重复回调幂等。基础设施失败默认最多自动重试 2 次，耗尽后进入待人工处理；学生 RE/TLE 不重试。界面支持有上限的结果查询，离开页面停止查询；这些机制仅用于生产模式。

沙箱要求：非 root、每次运行独立文件系统、禁止网络、禁止宿主挂载、禁止特权与设备访问、限制进程数/CPU/墙钟/内存/文件/输出、清理进程树及临时文件。默认单测试 CPU 2 秒、墙钟 5 秒、内存 256 MiB、输出 1 MiB；题目 CPU 上限 5 秒、内存上限 256 MiB，发布前以参考解答验证。JavaScript 的 Node.js 启动开销使 32 MiB 题目在沙箱语法检查阶段间歇性超限，因此 JS 的有效内存上限公开采用 `max(题目设置, 128 MiB)`；Python 与 C++ 仍严格按题目设置，工作区与题目 API 均显示该差异。C++ 编译也在隔离环境中，独立受 15 秒 CPU、30 秒墙钟、768 MiB 内存上限约束，编译产物仅用于本次任务并在完成后删除。单任务还共享累计 CPU 30 秒 / 墙钟 60 秒预算，防止大量测试无限占用课堂队列；预算耗尽按 TLE 结束，已通过测试保留分数。三种语言的实际运行时版本保存在评测环境标识中；部署镜像需固定摘要并在升级后重验。

标准 I/O 默认 token 比较（忽略空白分隔差异），需要严格格式的题目明确选 exact；换行规范化规则随比较器版本固定。首期不支持任意教师上传可执行 checker。

函数题通过受限 JSON 参数协议调用指定函数，JSON 返回值按类型与值比较（不将 bool 当整数）；异常为 RE，缺失函数或签名不匹配为 CE。Python 保持 `def name(*args, **kwargs)` 的原有调用习惯；JavaScript 提供同名函数，位置参数展开，非空命名参数对象作为最后一个参数；C++ 使用 `nlohmann::json name(json& args, json& kwargs)`，其中 `args` 为 JSON 数组、`kwargs` 为 JSON 对象。由于原题参数元数据为自由文本，不能自动推断任意 C++ 类型签名，工作区须展示该固定接口。每个测试在独立运行中执行；不修改输入的要求通过调用前后参数值比较检测。学生调试输出不作为返回值，且仍受限制。隐藏参数、包装器内部异常、标准答案和原始日志不回传给学生；安全隔离不能依赖函数包装器。

<a id="grading"></a>
## 6. 分数、订正与重判

每个正式测试保存权重，启用测试的权重总和为 100；原型对应的统一编辑器按启用测试等权分配，停用测试不计分，已有发布版本的权重保持不可变。通过测试累加题目百分比分，活动得分按活动题分值换算，最终显示保留两位小数。AC 当且仅当所有正式测试通过，得 100%；部分通过为 WA，不能出现 AC 80/100。WA 继续后续测试；CE/RE/TLE/MLE/OLE 立即终止本任务，未运行项不计通过，仍保留此前通过测试的权重分数。CE 无有效测试得 0。这一规则与总任务预算共同限制最坏运行时间。

System Error 无最终分数，等待有效评测，不当作 0 分，不覆盖已有有效成绩。作业默认取截止前有效正式提交的最高分，同分取较早接收提交；截止后拒绝带作业上下文的正式提交，可另做自由练习/订正，不计原作业成绩。教师发布作业时可只选择班内部分学生；未选中者不属于适用名单，也看不到该作业。作业发布后可修改标题、说明、课程、截止时间与适用学生；班级不可改，截止时间只能延长。题目集合、分值和顺序仅在该作业尚无正式提交时可修改；同题的固定版本只有在该作业完全没有运行或提交记录时，才可由教师显式切换到已发布的新版本，其他修改不得悄悄更新版本。已有正式提交后保留既定题目与成绩。有该作业运行或提交记录的学生不可直接从名单删除，需要时使用有原因记录的整项活动豁免；豁免学生不进入活动分母，不提供单题豁免。截止后变更名单需先显式延期并记录原因；计时训练发布成绩后不能改名单。

计时训练默认每题最后一次截止前接收的提交，结果尚未完成则标记待评测。该提交出现 System Error 时保留待处理状态，不能静默退回早期提交。教师发布前确认待处理项，默认阻止发布不完整成绩。

已发布作业的每次修订都记录操作者、时间与变更字段，不要求教师填写修改原因；使用作业编辑版本号防止旧页面覆盖其他教师的最新修改，发生冲突时提示刷新并重新核对。进度页的个别延期与豁免仍记录原因，并推进编辑版本号。

每道题默认提供首次 AC 奖励 10 积分；只有管理员可为题目单独配置 0–30 积分的首次 AC 奖励。个人积分账本对每道题只发放一次该奖励，无论是在自由练习、作业或订正中通过。全校榜使用独立的排名积分：仅管理员审核通过且已向全校公开的题目版本，才能在审核后新的有效正式 AC 时给学生发放一次校级排名积分；此前私有或待审题目的 AC 保留在个人账本，但不追溯上榜，学生在审核后仍可通过新的有效正式 AC 取得榜分。已发布但未公布成绩的限时训练须在首次公布后结算榜分。管理员设置的该题首次 AC 分值同时作为其榜分值，后续修改不重算已获得的榜分。

教师布置作业时，可在选题列表设置每题 0–20 积分的**作业额外奖励**，每份作业合计不超过 100 积分，默认 0；它与题目分值及首次 AC 奖励分别显示。学生在截止前对本作业该题正式提交并首次取得 AC 时，额外奖励只发一次；截止后的订正不取得原作业额外奖励。额外奖励受每周作业奖励 200 积分上限约束。奖励随作业创建或修订在同一事务内保存；已有正式提交后不能改动该作业题目的奖励，历史积分账本不会因之后调整奖励而重算。作业与限时训练的教师额外奖励仅进入个人积分及活动记录，不改变全校榜名次。

教师在发布限时训练前，可对每题分别设置 0–20 积分的固定 AC 奖励、速度奖励上限和少尝试奖励上限，三项合计的全场上限不超过 100 积分；已有训练默认三项均为 0。此奖励独立于考试题目分值与全站每题首次 AC 积分。以教师首次公布的成绩快照为准，仅当该题最后一次截止前正式提交为 AC 时结算一次：`固定奖励 + floor(速度上限 × max(0, (训练时长秒数 − 从开始到该 AC 接收的用时秒数) / 训练时长秒数)) + floor(少尝试上限 / 截至该 AC 的本题正式提交次数)`。提交越快、尝试越少，奖励不下降；没有符合条件的 AC 则额外奖励为 0。公布前可见规则与奖励上限，实际获得积分在公布后可见；成绩修订不会重新发放或追溯奖励。首次公布必须等待本场所有有效正式提交完成判题，并在同一事务内冻结判题状态、成绩与积分。个人账本中的全站首次 AC 奖励仍依据本次训练里曾经按时通过的正式提交，在首次公布时发放，即使最后一次提交为 WA；若该提交对应管理员审核公开的题目版本，校级排名积分同样在首次公布时结算。它们不计入本次训练额外奖励。本项不受作业奖励每周 200 分上限约束，教师应按全场 100 分预算设置。

校内积分榜默认按全校有效学生账号排名，宽屏使用原有内容区宽度；筛选器可查看任一未归档班级，学生不受自身班级限制，兼任多个班级也只在全校榜中出现一次。榜单按排名积分入账时间提供全部时间、本月、本周视图；月和周以 `Asia/Shanghai` 自然月、周一开始的自然周计算，同分并列。分页榜单列入全部有效学生账号，包括尚无榜分的学生；当前学生不在本页时仍可单独看到自己的名次。公开榜单使用学生自设昵称，未设置时显示“同学”，不公开实名、登录用户名或随机短编号。只有管理员能统一设置全校学生端是否显示`解题数`、`提交次数`和`AC 率`，默认隐藏提交次数；服务端同步省略隐藏字段，教师及管理员仍可看全部指标。`解题数`是对应时间内获得校级排名首次 AC 的不同题目数；`提交次数`统计已审核公开题目的有效正式提交，重复提交计次，样例运行和订正不计。`AC 率`是其中判为 AC 的次数除以已有有效判题结果的正式提交次数；等待中、评测中、系统错误不进分母。未公布结果的限时训练提交暂不进入公开榜单；训练首次公布时榜分与解题数入账，提交次数仍按原接收时间段统计。个人总积分可能高于榜分，界面明确区分。排行榜只提供教学参考，不把 AC 率称作未定义的 Win Rate，也不替代活动成绩。所有角色的头像菜单统一使用“积分排行榜”。

学生从全校或班级榜单头像、昵称进入同学公开主页；校内已登录学生、教师和管理员均可查看。公开主页展示自设昵称、头像、自愿填写的简介、个人累计积分及已公开的首次 AC 动态；不展示登录账号或实名。学生可给校内同学留言，主页主人、负责该学生的教师与管理员可删除留言；举报进入管理员处理流程。留言是有长度和频率限制的纯文本，举报与删除保留审计记录；未公布训练和未经管理员审核公开的题目不得泄露于他人动态。

订正为独立 Submission，记录 originalSubmissionId 与 ReviewEntry，不覆盖原活动成绩。重判增加 JudgeRun，保存旧结果、原因、操作者与新环境版本；管理员先查看候选结果，再明确确认或丢弃，确认前原提交成绩保持有效。已发布计时训练快照不自动替换，教师带原因发布新修订并保留旧版。

示例编号统一采用 SUB1042 / SUB1048；SUB101042 为旧文档别名，原型可兼容导航，生产采用服务端生成唯一编号。475/600 与 6/8 均为原型快照，不预填真实成绩。

<a id="timed"></a>
## 7. 计时训练与反馈

活动状态：Draft → Published → Running → Ended → ResultsPublished → Archived；题目版本、规则和适用名单发布时固定。学生尝试状态：NotStarted → Active → Finished。开始通过服务端事务建立唯一尝试，个人截止 = min(开始时间 + 时长, 活动结束时间)，个别延期显式记录新的截止和原因。客户端倒计时仅展示服务端时间差，不能决定是否接收提交。

接收时间 ≤ 个人截止的提交有效，即使排队/评测发生在截止后。截止后拒绝正式提交，草稿不自动转为提交；手动结束先确认未提交草稿提醒。断线重进恢复服务端尝试与已接收提交；代码草稿仅保存在当前浏览器会话，按账号、活动来源、题目和版本隔离，可恢复同一会话内的重载，不作为服务端已接收提交或跨设备备份。生产编辑器对站内导航、浏览器后退与刷新提供未提交变更提醒。

当前限时训练的正式提交会实时显示 AC、WA、CE 等判题状态；最终分数、隐藏测试细项与题解仍待教师发布结果后开放。历史 `showVerdict` 字段仅用于兼容旧活动，不再遮挡判题状态；普通练习可显示汇总测试通过数。教师预览不建立学生真实尝试，且必须显著标注预览。保密训练使用未公开的私有题库版本；已公开练习题无法重新成为保密试题。训练中的私有版本禁止绕过活动做自由运行或订正，包括引用旧自由提交的请求；结果发布后允许参训学生复习。

计时训练的题目分值与积分奖励分别配置和展示；发布训练即固定题目及奖励规则，已经发布的训练只能查看规则。教师发布成绩前核对待评测项及拟入账奖励；系统以首次公布的快照及服务端接收时间计算奖励并写入唯一积分账本，重试和后续成绩修订不重复给分。

<a id="imports"></a>
## 8. 导入与内容发布

统一四阶段外观，分别使用身份导入与题目导入契约，不能共用账号创建逻辑。身份导入以类型+编号去重，姓名不作为唯一键；重复编号但姓名不同需人工处理；已激活身份不重新生成账号或激活码。管理员全校身份导入支持 CSV/XLSX/JSON，可选择已有班级、无班级或明确按文件班级列建立/引用班级；教师只能在所选负责班级导入学生，建立新身份或引用本人教学范围中的已有身份，不清除原班级成员关系，也不能通过文件创建其他班级。预览错误行可跳过，确认后返回逐行成功/失败及原因；同一请求鍵的断线重试不重复建档或发码，短期重放凭据加密并设 15 分钟有效期。

生产导入由服务端再次校验，浏览器 Excel/题包解析仅供预览，不构成可信导入结果。浏览器名单文件最大 2 MiB、每次界面最多 500 行；全校身份 API 批次最多 5000 行、教师班级批次最多 500 行，题目导入最多 100 题，API 请求总大小最多 2 MiB。题包支持 JSON 清单，以及标准 ZIP 中的 `problem.md`、公开样例与正式 `.in/.out` 配对、可选 JSON/YAML 配置、参考解和模板；配置与 pid 可省略。103 行输入的一对文件仍是一组测试，不按输入行拆测试。

ZIP 只在浏览器内解析，不在服务器目录解压或执行条目；压缩文件与展开内容合计均限制 2 MiB、最多 512 个文件/目录，同时检查 CRC、头部一致性、重复路径、压缩比、路径穿越、加密条目和符号链接。YAML 禁止执行型标签、重复键和循环引用，并限制别名展开。规范化题目通过既有服务端 JSON 草稿接口导入；参考解缺失等可保存待完善草稿，只有真实验证通过才可发布。题目来源元信息不自动授予权限或覆盖题号、历史成绩。

题目只进入草稿；正式测试必须存在、可解析、权重合法，并通过参考解答校验才能发布。样例与正式测试分库存放；权限和文件下载接口禁止向学生返回正式测试。首期不提供从不可信远程 URL 自动下载题包。

<a id="operations"></a>
## 9. 运维与隐私

校内部署仍使用 HTTPS。密钥由部署配置提供，不进入仓库；数据库与判题节点仅开放必要内网端口。健康检查区分 Web 可用、数据库可用与判题可用；节点故障应提示等待，不产生学生错误分数。记录队列长度、等待时长、失败率及资源使用，不以页面固定快照代替监控。

审计覆盖认领、重置、账号禁用/换绑、权限变更、题目发布、成绩修订与导入；不记录密码、激活码、隐藏输入或完整学生代码。管理端审计查询再次按字段白名单脱敏。恢复为学校服务器 CLI 操作，由学校保留维护记录；没有网页恢复接口。个人信息、代码和成绩只供授权教学用途；首期不自动删除历史，留存/归档周期与备份清理由学校制定后执行。

每日数据库备份，包含所有私有题目测试与代码，首期目标 RPO 24 小时、RTO 4 小时；上线前必须完成学校独立环境恢复演练并验证账号、版本、提交、活动快照关联。恢复需停止 API/worker 并由管理员在服务器明确执行，不从学生页面触发。

<a id="delivery"></a>
## 10. 实施顺序与验收

1. 基础设施：数据库迁移、部署配置、会话与权限、初始化管理员、备份；保留原型模式。
2. 身份与班级：名单导入、激活、登录、重置与多班级；生产页面接入真实数据。
3. 题库与版本：编辑器、分组、私有测试上传、参考解答校验与发布。
4. 核心评测：自测、幂等正式提交、沙箱、结果查询、作业计分与订正。
5. 教学扩展：计时训练、学习内容、报告、运维界面与生产验收。

每阶段必须有真实端到端演示，不能用固定 AC、虚假导入成功或内存成绩替代。必要自动化验证：并发认领、重复提交、越权读取、截止边界、题目修订不改历史、故障不计零分、租约过期重复回传、隐藏测试不泄露、禁网/进程/资源限制、导入越权与重试、备份恢复。跨浏览器验收目标为 Chromium、Firefox、Safari 及 390/768/1280/1440 宽度；本次实际覆盖见部署记录，不将目标写成已验证结果。

上线负载基线为 30–50 名同时在线学生、总账号约 200，峰值每秒 5 次提交仅作为压测目标而非已验证能力；初始 worker 并发固定为 2，必须按学校实际机器性能调整并公布限制。未通过沙箱、授权、真实评测和恢复验收前不得标记“可供学生正式使用”。

## 11. 部署前待确认条件

- 已确认学校主机 Ubuntu 26.04、4 核 / 8 线程、16GB、Docker，以及总学生约 200、同堂 30–50 人；仍需在该机器验证 cgroup/系统调用隔离与课堂容量。
- 网络访问范围与校园 HTTPS 域名、实际证书入口。
- 题库来源、参考解答与正式测试是否齐备，以及学校的资料留存周期。

这些学校侧条件不阻碍当前开发与本地验收，但阻碍正式部署和学校容量承诺。改变取分方式等教学规则时需更新本文与决策时间线，不能仅修改页面文案。
