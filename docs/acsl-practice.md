# ACSL 真题练习

当前分轮题库覆盖 2020–2021 至 2025–2026 六个学年，Elementary、Junior、Intermediate、Senior 四个组别，每组四轮，共 96 份试卷、512 道笔试题和 72 道编程题。Elementary 的 24 份试卷只有笔试。原 Junior 2025–2026 第三轮样板保留原内容、版本和作答记录。题库支持单选与多选；多选按完整选项集合判分，顺序无关，漏选和错选均判错。

## 学生流程

指定学校启用试卷后，学生侧栏出现 ACSL practice／ACSL 练习。原学校入口为 `/student/acsl`，其他学校使用 `/schools?schoolId=…&section=acsl`。目录按学年倒序分组，组别顺序固定为 Elementary、Junior、Intermediate、Senior，组内按轮次排序。默认展开最新学年，可继续展开更早学年，也可筛选学年、组别、轮次。筛选和展开状态保留在 URL，并按账号、学校保存到当前浏览器。进入试卷、切换页面、刷新或重新打开浏览器后恢复；显式带筛选的链接优先，重置也会被记住。浏览器禁用本地存储时仍可通过 URL 保留选择。目录显示已作答题数、交卷后的笔试得分及编程通过状态；已交卷试卷通过“成绩与复盘”进入复盘页，满足全部完成条件的试卷显示“整卷已完成”。

笔试选项保存到账号，带草稿修订号。一次成功保存使全部笔试题都有已保存答案、待复核题均已确认且没有保存或冲突阻塞时，页面静置 1.2 秒后提示是否交卷，默认操作为“继续检查”。连续修改多选答案会重新等待；提示本身不提交答卷。当前浏览器会话按账号、学校、试卷及笔试修订记住已提示状态，手动打开交卷确认也会消费这次提示，关闭后不反复弹出。直接重新打开已经保存完整的试卷不会触发自动提示，学生仍可使用交卷按钮。

学生明确确认交卷后，服务端按同一试卷版本一次判分并锁定这次答卷。交卷前只显示作答进度。成功后弹出结果摘要，显示实际笔试成绩、编程状态和服务端确认已获得的积分及其笔试／编程分项，不把规则中的预计奖励当作到账积分。复盘入口可查看全部题目或仅错题，显示提交时的真实选项、本人选择及逐题对错；每题点击“查看解析”后才请求并打开对应解析。全部答对时，“仅错题”提供空态和返回全部题目的操作。保存失败保留当前选择并支持重试，多标签冲突由学生明确加载服务端已保存答案。历史逐题提交保留，整卷判分使用交卷时核对过的草稿，重试同一次交卷返回已保存的结果。

题面语言独立于界面语言，可选择已有英文或中文。编程题独立使用共用 `ProblemWorkspace`、编辑器、代码草稿、自测和正式提交，随时可运行或提交。正式提交获得 AC 后，页面重新读取服务端试卷状态，再显示阶段结果；样例和自定义运行的 AC 不算编程完成。若先通过编程，摘要显示笔试待交卷并提供“继续笔试”；若笔试已交卷但编程尚未通过，则提供“继续编程”。刷新进度失败时保留判题结果并可重试，不根据客户端推算完成状态或奖励。

“整卷已完成”表示笔试已交卷，且有编程题时已正式 AC。Elementary 仅需笔试交卷，不要求笔试满分。再次打开历史成绩时，学生可手动打开结果摘要。目录、试卷、复盘及编程之间的导航保留筛选与题面语言，返回笔试保留当前题号。

## 教学解析

笔试解析按题目逐步说明如何得到答案。进制题写出位权、进借位或分组，表达式题写出操作数顺序和关键运算，程序与递推题追踪决定结果的变量或分支，图论和状态机题给出可核对的路径、状态或计数。复杂题保留所需的表格、公式和原生图。已有充分推导的题目沿用相应深度，原卷勘误和本站独立推导的出处一并保留。

演示多位数加法时使用 KaTeX 竖式。各数按个位对齐，进位写在接收它的列上方，横线下写和。混合运算用竖式展示加法步骤，再继续解释剩余运算。

新交卷的学生通过“成绩与复盘”打开当前双语解析。已有冻结快照的答卷继续显示交卷时的版本，未冻结的旧答卷可阅读当前解析。教师题库与教师答案解析版导出也使用当前解析。解析扩充走 092 的审计事务，发布前核对旧内容哈希及完整题目定义，只允许两种语言的解析正文变化。实际检查见[验收记录](acsl-validation.md)。

## 教师管理与导出

原学校教师从 `/teacher/acsl`、管理员从 `/admin/acsl` 进入 ACSL 题库；其他学校使用学校工作区的 ACSL 题库入口。管理目录按当前学校列出全部已导入试卷，不限于导入者本人，也不要求先以学生身份作答。教师可直接查看双语题干、真实选项、正确答案、解析及原生公式和图形。目录沿用学年、组别、轮次筛选和本浏览器记忆。

编辑支持双语标题、笔试题干与主题、选项内容、正确选项、解析以及受限原生图元；编程题可修改标题、双语题面及图形。题目和选项 ID、顺序、题型、编程样例、正式测试、比较器、资源限制、参考程序及积分规则保持固定。图形编辑使用结构化 JSON 并在保存前校验，不接受截图、任意 SVG 或 HTML。保存需填写修订原因，页面预览与学生页复用相同的 KaTeX 和 SVG 渲染组件。

迁移 `094_acsl_management.sql` 增加受控教师修订函数与前后内容审计。API 和数据库函数分别校验目标学校的有效教师／学校管理员权限；应用角色只能调用受限函数，没有直接更新题库、修改历史快照或审计记录的权限。保存携带原内容哈希和幂等请求 ID；并发过期保存返回 409，保留教师输入供核对。每次笔试修订沿用 093 的历史快照机制，保存旧题、旧答案和旧解析；新交卷使用新笔试修订。修改题干、选项或答案键时，由服务端判定待复核题，未交卷学生保留选择并重新确认。旧成绩、旧答卷、积分与奖学金不重算。

每卷可导出英文或中文的学生卷、答案解析版，在独立打印预览页通过浏览器“打印／另存为 PDF”保存。学生卷接口按白名单构造题干、选项、图形和编程公开样例，不返回答案或解析；预览不请求教师详情。教师版增加笔试答案与解析。完整 JSON 备份包含双语内容、图形、正确答案及现有编程判题数据，应作为教师资料保管；三种导出均不包含学生账号、作答、成绩、提交或审计记录。本次提供单卷导出，不包含批量打包功能。

管理读写与导出均走独立的 `acsl/manage` 接口并使用 `private, no-store`；学生、他校教师、撤销身份与停用账号不能访问。学生笔试解析仍要求交卷；编程参考实现使用下述奖学金解锁规则。教师管理使用独立的教师权限。

教师在试卷详情的“编程题”中设置参考实现与解析的查看金额。每题默认 12 奖学金，可设置 0–1000 的整数；留空恢复默认，0 表示免费。金额对本校该题所有学生生效，保存不修改题面、判题版本或既有成绩。价格使用独立修订号防止并发覆盖；已购买学生不会补扣差价。普通编程题沿用原有的单题及批量奖学金定价入口和学校默认价格。

## 数据和访问

迁移 `088_acsl_practice.sql` 添加学校作用域试卷、草稿和提交表。每张已导入试卷绑定内容哈希、笔试版本和编程版本。相同内容重复导入返回现有试卷，内容不同的同名导入被拒绝；仅展示修正使用下述 092 审计更新。经明确审核的题文/选项含义校订使用下述 093 笔试修订机制；答案键、选项 ID、题序、权重或编程判题规则改变仍不属于该机制。

迁移 `089_acsl_paper_grades.sql` 增加按学校、账号和试卷版本保存的整卷成绩。交卷通过 `POST /schools/:schoolId/acsl/:paperId/submit` 核对每道笔试题的草稿修订号，单次事务记录选择和得分。原逐题提交端点提示使用整卷交卷，解析端点要求已有整卷成绩。

迁移 `091_acsl_source_assets.sql` 支持无编程题的试卷及历史私有图片资料。当前题库已改为原生呈现：题干、真实选项、KaTeX、代码块和表格分别渲染，图形使用受限 SVG 图元。题面与答案解析分开投影；解析图与文字同样要求先交卷并主动展开。编程适配器在共用工作区内渲染原生题面，正式测试和参考解仍留在服务端。

迁移 `092_acsl_presentation_updates.sql` 为已导入内容提供展示修正审计。领域层以单一事务锁定待更新试卷，核验旧内容哈希及不变的判题字段，只更新展示定义并保存前后快照；试卷和题目版本、草稿、成绩、提交、奖励规则及历史流水不变。旧裁图移出当前内容包，已有资料表保留，当前定义不再引用的图片不能由学生接口获取。

迁移 `093_acsl_written_revisions.sql` 为经审核的题文/选项含义修订增加独立的 `writtenRevision`。维护者在 092 更新清单中显式提供 `changedQuestionIds`（本次正则题为 `['q6']`），在同一学校排他事务锁内保存既有整卷答卷的原题和解析快照、退役逐题记录的原题审计，再更新当前题目及笔试修订标识。整卷答卷、成绩、草稿选择与修订号、编程版本、积分唯一键和流水不改写；新交卷也由数据库触发器保存不可变题目快照。应用只能读取整卷题目快照，worker 无读取或写入权限。

详情接口按当前用户的历史成绩读取相应题目快照；解析仍在交卷后单独读取。未交卷学生看到当前校订版，旧草稿继续保留，受影响且尚未重新保存的题返回 `requiresReview`。页面提供确认原选择按钮，并在全部待复核题确认前禁止交卷。PATCH 草稿和 POST 交卷携带 `writtenRevision`；修订前旧页面的缺失或过期标识返回 409，不能静默按新选项提交。已交卷请求重放直接返回原成绩，不重新发分。此机制不公开正确选项、修订前后解析或审计快照；前端只接收当前用户有权查看的题面和状态。

Nest 的 ACSL 接口位于 `schools/:schoolId/acsl`。每次访问重新检查有效学校身份和试卷开放状态。目录、题面、答案解析、草稿和编程记录均由领域层检查权限。学生只能读取自己的作答和编程源码。程序通过 `school_judge_jobs` 的 `acsl` 上下文交给既有隔离 worker 和执行器。

ACSL 的编程资源使用专用题库类型。普通题库读取、恢复、发布及直接判题记录入口会拒绝这类资源。ACSL 正式提交只返回允许展示的状态和统计，样例和自定义运行按现有规则展示。应用与 worker 继续使用独立 PostgreSQL 角色，worker 无权读取笔试答案表。

## 校内练习积分

天行创世纪学校的分轮题库沿用已验收的积分规则：笔试交卷后每答对一题得 1 分，编程首次正式 AC 得 10 分。两部分分别结算，并计入个人积分和校内排行榜。Elementary 只结算笔试积分。积分与试卷成绩、奖学金分别记账。历史成绩不补发，样例、自测和未通过的正式提交不计分。

迁移 `090_acsl_points.sql` 只增加结算机制。由迁移角色为指定学校、试卷和版本在 `acsl_point_rules` 中添加启用规则，普通导入不会自动开启。笔试判分与积分在同一事务保存。编程正式提交时记录资格和金额，worker 写入判题结果时一起结算。积分按稳定学生身份和试卷的笔试、编程两部分各记一次。重复请求和重复通过不会重发。

## 指定学校导入

使用私有配置提供迁移角色 `DATABASE_URL`，依次运行迁移、角色授权和导入。学校及负责人账号使用真实 UUID。

```sh
node packages/domain/src/migrate.mjs
node packages/domain/grants.mjs
node packages/domain/src/acsl-import.mjs --school-id SCHOOL_UUID --owner-account-id ACCOUNT_UUID
```

默认包为 `packages/domain/content/acsl/sample.json`。包内包含教师参考程序和正式测试，按服务端资料管理。来源哈希、页码和转录约定见同目录 README。原卷第 5 题题面使用 `count != 3`，答案册使用 `count < 3`，样板保留题面写法，解析标注该差异。公式逐页核对，树和牌局图采用可阅读的表格及文字示意。

新增内容按 `packages/domain/content/acsl/editions/<学年>/<组别>/contest-<轮次>/paper.json` 保存，题干、选项、解析及安全图元均保存在内容包内。先校验全部包，再以单个事务导入；任何一个包校验失败或与同名已导入内容冲突，都不会留下半批数据。

```sh
node packages/domain/src/acsl-import.mjs --directory packages/domain/content/acsl/editions --dry-run --enable-points
node packages/domain/src/acsl-import.mjs --directory packages/domain/content/acsl/editions --school-id SCHOOL_UUID --owner-account-id ACCOUNT_UUID --enable-points
```

`--enable-points` 为显式开关，当前限已支持统一校内积分的原校作用域。导入和启用规则在同一事务中完成；重复导入不改原版本、不重设积分规则启用时间、不补发旧成绩。编程题采用官方样例和正式测试作为判题依据，全部 72 道另有 Python 3 参考实现，保存在 `programming.solution`。每次执行只读取一组标准输入，PDF 的展示换行和题号已转换为实际输入格式，题面说明和可复制用例明确这一约定。

原目录的 19 组早期专题汇编包含填空和自由作答题，并非按学年、组别、轮次组织的完整选择题试卷。它们单独编入内容目录，保留原卷和答案来源，不虚构选项或自动判分。

本地验收使用独立 `campus_qa_acsl_20261109` 数据库和临时账号。试点学校为本地 3004 环境的天行创世纪学校，学生通过 `/student/acsl` 进入。验证记录见 `acsl-validation.md`。

## 编程参考实现维护

教师详情和答案解析版显示“参考实现”，包含完整 Python 3 代码、双语算法说明及复杂度，并支持复制代码。学生编程页在题干区顶部始终显示 Solution 页签，允许在正式提交前用奖学金解锁。确认前只提供价格、翻译抵扣及余额，不预载答案；确认购买后才读取代码和所选语言的解析。本人正式提交通过（AC）后可免费查看，含经审计的旧判题版本；样例与自定义运行不产生此免费资格。

题解费用按本校该题设置计算，默认 12；已付翻译费用按未退款的实际支付金额抵扣，最低扣款为 0。抵扣到 0 时仍建立已购买权益，已用于抵扣的翻译不能单独退款。一次购买覆盖该题的双语解析及后续发布版本，刷新、重看和调价不重复收费；老师设为 0 时的免费查看不建立永久付费权益。未购买且不满足免费条件时，直接请求解答接口仍被拒绝。查看内容不改 ACSL 成绩和校内积分。

Problem 提供英文编程题面。Translation 提供已审核的中文题面及图形，按当前学校配置报价并使用对应的奖学金余额。确认后同一题仅扣款一次，重看使用原权益。Tutorial 在题包提供教程时显示。

新增解答通过已有 092 展示修正审计事务发布，保留试卷、编程和笔试修订版本、正式测试、草稿、成绩和积分。维护命令只合并 `programming.solution`，保留教师已修改的笔试内容；编程规则、题面或图形与已审核实现不一致时拒绝发布。默认仅预检，指定 `--apply` 才写入。

```sh
node packages/domain/src/acsl-solutions.mjs --school-id SCHOOL_UUID --actor-account-id ACCOUNT_UUID
node packages/domain/src/acsl-solutions.mjs --school-id SCHOOL_UUID --actor-account-id ACCOUNT_UUID --apply
```

校验命令使用配置好的隔离执行器，逐题执行公开样例、正式数据和另行推导的边界用例，输出实际通过数量及代码 SHA-256。连接参数用私有环境文件提供。

```sh
node scripts/validate-acsl-solutions.mjs --report PRIVATE_REPORT_PATH
```

本轮发现并核实 Senior 2023–2024 第四轮正式测试 5 的末项应为 `2048`：原 PDF 英文第 6 页截为 `204`，中文第 12 页保留完整数值。该项不走 092 展示更新，而由 `095_acsl_programming_revisions.sql` 和 `acsl-programming-revision.mjs` 创建新的不可变编程判题版本。维护清单必须提供旧内容哈希、幂等请求 ID、测试下标、完整旧／新预期输出及原 PDF 哈希、页码。输入、权重、样例、比较器、资源限制及其他内容不能通过此操作改变。

历史版本关系仅供应用读取学校范围内的版本 ID；worker 无审计读取权。旧提交及原 AC 继续显示，旧版页面的新提交返回 409，已排队任务按原快照及奖励资格继续完成。笔试版本与成绩、草稿及既有积分均不重算。
