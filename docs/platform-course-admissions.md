# 平台课程开放范围与准入

平台课程的维护、规则配置和入课审批均由平台管理员负责。学校教师、学校管理员不能修改平台源课程，也不能借学校审批入口授予平台课程资格。

## 范围与条件

开放范围分为“所有注册用户”和“自定义范围”。自定义范围可组合：

- 未加入任何学校的个人用户。
- 指定学校的有效成员；每所学校独立设置规则。
- 指定账号；身份选择包括自由注册账号与学校账号。

个人用户按当前学校关系判断，不按注册方式、`identities.kind`、默认学校或当前工作区判断。新学校学生也可能使用 `personal` 全局身份。切换到自由练习页面不会改变所属范围。多个适用范围取并集，但必须完整满足其中一条规则，不能把 A 校的成员资格与 B 校的积分或审批拼起来使用。

每条规则包含：

1. **学习门槛**：可选择前置平台课程及最低积分，未设置则无此门槛。
2. **准入方式**：直接学习、申请后由平台管理员批准、凭 6 位邀请码加入。

审批与邀请码仅完成准入步骤，不能跳过所属范围或学习门槛。账号和学校资格、条件及当前准入规则在读取课程、标记阅读和使用课程练习上下文时统一核验。失去权限不删除已有学习进度、答卷、成绩或奖励。

所有受众使用同一个平台积分余额。积分按登录账号归属，退校后继续有效。原有正式题、Paper 4 和 ACSL 已发积分保留。平台审核通过的普通题在校内或公开入口正式通过后计入，同一题跨入口只算一次。公开榜单参与设置不影响资格积分。积分门槛只读取余额，不扣分。

前置课程必须是可用的平台课程，且有有效章节。完成要求是全部有效章节已读、所有配置的正式练习完成；没有练习的课程可按阅读完成。不可用、无访问权限或版本失效的练习不能从分母中排除后按完成处理。正文中的原创自测没有独立判分记录，不作为自动判定条件。禁止课程依赖自身或形成前置循环。 每门前置课及正数的积分门槛各算一项。管理员可选择全部满足或满足任一项。现有规则默认全部满足，原门槛数值与受众沿用。

## 申请与邀请码

学生只在符合范围且达到门槛后申请或兑换邀请码。课程目录可显示符合范围但尚未获准入的课程简介、当前缺少条件及申请状态；正文、参考答案、学习资源和课程练习上下文继续受准入保护。

平台课程中的“学习申请”与学校课程的“上架审核”是不同流程。平台管理员可以查看当前入课记录、批准或拒绝申请、撤销已授予的准入。审批记录与课程正文修订分开：普通文字、翻译修改不让学生重新申请；改变相关准入规则会使旧代次授权失效。旧记录仍保留用于追溯。

邀请码固定 6 个字符，以密码学安全随机方式生成，绑定课程和具体规则。只在明确生成或重置成功时显示明文；不写入 URL、本地持久存储、普通读取响应或审计正文。持久化的是验证摘要。邀请具有有效期，可以重置或停用；兑换必须登录、验证 CSRF 并受持久化尝试限制保护。

默认有效期为 7 天，管理员可选择 1–30 天。指定账号与指定学校一样分别拥有规则；一个账号同时命中多条规则时，选择其中一条完整满足的规则申请或兑换。学校的邀请码不能用于没有该校成员资格的个人账号。

重置或停用邀请码阻止后续兑换，不自动撤销已成功加入的学生。平台管理员可在入课记录中单独撤销资格。更改准入规则则按新的规则代次处理，不能通过旧邀请码或旧批准重新获得访问。

## 既有数据与真题边界

已有全平台、指定学校、指定学生配置迁移为等价的直接准入规则，不自动扩大已发布课程的范围。ACSL Intermediate 课程的具体规则由平台管理员自行选择，本次功能升级不替管理员配置自由账号开放或学习门槛。

平台课程的公开学习资格与关联试卷权限分别核验。课程获批不会自动取得某所学校的 ACSL 试卷资格；正式题答案和解析继续遵守原交卷规则。课程 ID、章节 ID、历史阅读记录及题目版本关联保持不变。

## 接口与规则版本

平台课程读写的 `audiencePolicy` 包含 `scope`、`allRule`、`independentRule`、`schoolRules` 和 `accountRules`。规则保存准入方式、前置课程 ID、最低平台积分和门槛组合 `requirementMode`（`all`／`any`）；学校规则使用 `schoolId`，指定账号使用稳定的 `identityId`。服务端生成 `ruleId` 与 UUID `generation`。保存课程继续使用 `expectedRevision` 和 `sourceVersion`，不以客户端规则版本代替课程并发控制。

| 入口（均位于 `/api/v1`） | 用途 |
| --- | --- |
| `GET /platform/courses/:id/admissions` | 平台查看学习申请及已授予的准入 |
| `POST /platform/courses/:id/admissions/:applicationId/decision` | 按预期状态和规则代次批准、拒绝或撤销 |
| `POST /platform/courses/:id/rules/:ruleId/invitation` | 生成／重置或停用邀请码 |
| `GET /practice/courses/:id/entry` | 学生查看适用规则、门槛进度和申请状态 |
| `POST /practice/courses/:id/applications` | 对当前代次的规则提出申请 |
| `POST /practice/courses/:id/invitations/redeem` | 对当前代次的规则兑换邀请码 |

平台申请、邀请码与失败次数使用独立数据表，不复用学校入校邀请或学校课程上架审批。邀请码验证失败次数跨 API 实例持久化；错误响应不会回滚已经记下的失败次数。纯内容修改保留规则代次；准入方式或门槛修改、移除后重新加入该规则都会使用新代次。
